# Agent 规则维护

## 快速打开配置

Codex 发送 `$agent-instructions-update 配置` 或 `$agent-instructions-update 打开设置页面`；Claude Code 将 `$` 换为 `/`，WorkBuddy 明确选中本 Skill 后发送相同短语。配置/设置的八种短语均可直接打开已有页面，返回有效链接和实际空闲期限；缺少业务配置也能打开。附带业务正文或启动参数时继续原业务流程。

0.2.0 配置快捷入口已在 Windows 原生 Codex 0.169.0 默认沙箱完成实际调用、页面授权 HTTP 访问和停止验证；macOS 待验，Claude Code 未实测，WorkBuddy 本批按用户决定跳过。此次未调用付费业务或重跑完整业务流程。

在多个 Agent 和项目之间检查规则入口、审阅正文、同步独立副本，并在写入前展示具体差异。支持管理 Codex、Claude Code、WorkBuddy、Hermes、OpenCode；其他六种主流产品会列为尚未支持。

当前版本为 0.2.0，新增配置页面快捷入口。0.1.1 已修复参考资料被误列为场景的问题：仅从实际规则入口沿有效读取链识别场景，Skill 使用说明另按其职责保留。专用工作台已接入真实文件和维护任务；此前 Windows 原生 Codex 0.166.0 与浏览器代表性流程的验收仅覆盖其原版本和范围。macOS 待验，Claude Code / WorkBuddy 执行本 Skill 尚未实测。检测到规则文件不代表对应 Agent 已加载或行为已验证。

## 安装与第一次使用

将下面一段复制给 Codex、Claude Code 或 WorkBuddy。

> 请安装完整的 agent-instructions-update Skill 0.2.0，优先使用 https://github.com/cookaihq/cookai-skills 的 agent-instructions-update/v0.2.0 tag 中 agent-instructions-update 目录，遇到网络故障时自动尝试同项目 https://cnb.cool/zhidateam/tannt/tannt-skills.git 的同名目录并核对相同版本。沿用已有设置，并验证当前 Agent 能发现和调用。

安装由 Agent 按当前宿主的原生入口完成：Codex 使用个人 `.agents/skills/`，Claude Code 使用 `.claude/skills/`，WorkBuddy 使用其个人 Skill 管理入口。复制安装带上整个 Skill 目录，不能只复制 `SKILL.md`。需要 uv 和固定 Python 环境，Agent 会按随包锁文件检查准备；本工具不需要 API Key，也不另接模型服务。

先做只读检查：

> 请使用 Agent 规则维护，检查本机 Agent 和当前项目的规则。列出安装、入口、实际文件及共享关系，标明哪些加载行为尚未验证，先给我布局分析。

你会得到本机当前原生环境的发现结果。Windows、WSL、远端和其他用户分别检查；本工具不扫描全盘。发现文件、解析链接、确认宿主加载是不同结果。

## 常用请求

- “结合我指定的两个模型审阅这些规则，保留我的操作偏好，逐项说明依据、影响和候选修改。”得到可逐项采纳的建议；没有行为证据的结论会保留待验证标记。
- “用 A 作权威，B 合并、C 为空、D 覆盖，E 不动。”只有 A+B 参与语义合并，整批等待确认后 A/B/C/D 一致；共享实体的别名会明确列出联动。
- “把这个场景规则改名，同时修复所有已知引用。”正文、引用和入口一起进入计划。
- “将规则放到我选的物理目录，并调整这些宿主入口。”先展示新布局、内容、链接与恢复位置；已有不同正文先合并。
- “查看上次任务，按当前文件给我一份恢复计划。”先比较现场，再确认具体恢复内容；旧快照不会自动覆盖后续编辑。

规则审阅由当前 Agent 完成。最终计划只需在对话或 UI 中确认一次；有效确认可以沿用。身份提示和记忆文件单独维护，默认不参加工作规则整篇同步。

需要浏览文件、批量比较或编辑场景时，可以说：

> 请打开当前项目的 Agent 规则维护工作台，让我选择权威文件和同步目标；需要合并时，我会把页面上的任务提示交给你，完成候选后回到页面刷新查看。

工作台包含检测、同步、场景、存储与入口、审阅、历史及一个设置页。顶部持续显示当前维护的是全局规则还是具体项目；没有项目规则时项目选项置灰，可选择项目或先预览建立规则。场景左侧按实际文件夹分组，以正文首个一级标题作为名称，并显示文件名。修改标题只改变名称，改文件路径另做计划。

页面显示真实文件和待确认计划。只选择空目标时可按已经展示的清单直接同步；有合并目标时整批等待。页面关闭或服务结束不会删除维护任务，重新打开后可使用同一任务标识继续。统一工作台默认空闲 60 分钟结束，实际操作续期。

**📱 手机或其他设备访问需要 FRP 或 Tailscale。** 可让 Agent 核实实际通道并提供可用链接；本机地址不能直接当作手机地址。

## 设置保存在哪里

默认个人设置在 `~/.config/agent-instructions-update/.env`，历史在同目录 `history/`。`~` 是实际运行用户的主目录；Windows 原生与 WSL 各自独立。每个项目保留自己的目标绑定，切换项目不把旧草稿套到新项目。

| 运行环境 | 默认个人设置位置 | 验证范围 |
| --- | --- | --- |
| Windows 原生 | `C:/Users/<当前用户>/.config/agent-instructions-update/.env`；以 Python 识别的用户个人文件夹为准 | 路径、Codex 隔离业务、UI 创建任务→Agent 回传→UI 确认、七页代表性操作已验收 |
| macOS / Linux | `/Users/<当前用户>/.config/agent-instructions-update/.env` 或 `/home/<当前用户>/.config/agent-instructions-update/.env`；以运行用户主目录为准 | macOS 尚未实机验证；Linux 尚未验证，不作为本版已验收平台 |
| WSL | Linux 发行版内 `/home/<当前用户>/.config/agent-instructions-update/.env`，与 Windows 用户文件夹不同 | 尚未验证，不自动读取 Windows 侧设置 |

业务入口按 Python 的用户主目录定位；Windows 更新检查按 PowerShell 的用户个人文件夹定位，macOS / Linux 的更新脚本按运行它的 Shell 用户主目录定位。切换用户或 Shell 环境时可让 Agent 核对实际位置。显式指定的测试目录不改变以上默认位置。

> 请保存我的常用目标和历史保留数量，默认供我个人跨项目使用；核对当前项目的绑定，告诉我保存位置和实际生效来源。

普通配置优先顺序是运行程序时的环境变量 → 所选工作文件夹 `.env.agent-instructions-update` → `.env.local` → `.env` → 个人配置。每项取首个非空来源，完整目标绑定不跨层拼接。页面会先从启动目录定位项目，配置只查页面选定的项目目录；对话入口只查显式指定的工作目录，不向父级逐层拼接配置。入口已启用个人设置，需要本次关闭可直接告诉 Agent。

只有明确要求当前项目覆盖时才保存到项目 `.env.local`。保存设置不会搬规则或改宿主模型；审阅模型默认只属于本次任务，明确要求复用才保存。全局和每个项目分别默认保留最近 30 个已完成任务；未完成和待恢复任务保留。

## 发生变化或失败时

“文件在确认后被其他会话改过”或“写入结果不明”时，告诉 Agent：

> 请先读取这次维护任务和当前文件，保留候选，说明已写、未写、不确定和待恢复项，再给我可核对的新计划。

工具会在写入前检查正文、实体和链接。中途失败停止后续写入，能确认安全时恢复；存在后续编辑时保留现场。恢复目录或快照只是依据，恢复成功需要实际回读。多文件操作不承诺跨文件系统整体原子性。

规则出现不可读、自定义 Profile 未选定或模型未知时，让 Agent核对具体位置与来源。不能因默认位置缺文件就认定没有规则，例如 OpenCode 可能使用 Claude 的回退入口。

## 更新

每次调用自动检查更新，检查失败继续当前任务；实际更新需你同意。可说“检查 Agent 规则维护的更新”或“关闭这个 Skill 的自动检查更新”。更新开关仅使用个人配置中的 `AUTO_UPDATE_CHECK`，不接受进程或项目文件覆盖。
