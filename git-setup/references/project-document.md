# 项目 Git 使用说明

先读取目标项目实际 Agent 入口、其必读文档及已有 Git 规则，优先更新同主题正文和有效入口；缺失时才新增。无既有约定时，正文为目标项目根下 docs/agents/git-repository-operations.md，标题为“Git 仓库操作规则”。Claude Code、Codex、WorkBuddy 实际规则入口均引用同一正文，保留已有 symlink。引用应明确触发条件：“执行本项目 Git 设置、读取、提交、推送或发布前，必须读取并遵守[Git 仓库操作规则](相对路径)。”

正文中项目路径以明确的项目根为基准，Markdown 引用以规则实体所在目录为基准；跨目录引用说明相对位置关系。其他设备保持这些相对路径及目录关系，绝对根目录可不同。项目已有共享文档锚点沿用其声明。子仓独立打开时核对自身适用入口，不以外仓已接入推断子仓已加载。

## 交付内容

Agent 根据当前项目填写下列内容，不把模板占位符当成完成结果：

1. 项目主要仓库的已确认选择、项目内相对路径、完整远端身份和其他仓库用途；子模块或独立仓的登记依据；各仓主检出与 Worktree 的关系。项目级请求默认选主仓，明确选仓或更严格项目规则优先；每次核对实际操作检出。主仓选择不得从外仓、origin、同名分支或目录嵌套推断。
2. 每仓主要远端、remote 名称、无凭证完整 URL、拉取 / 推送用途、允许的引用与同步方向；分支、提交身份和创建/提交/推送授权。记录实际 branch remote / merge / pushRemote、remote.pushDefault 及分支例外，区分规则约定和已应用配置。IDE 当前检出和显式 remote 参数决定按钮目标，主仓正文不重定向按钮。
3. 每个完整目标默认复用的项目 Token 来源及主检出内实际相对路径；全局 gh 仅在用户明确选择（含可核验的同范围既有选择）时使用指定账号，发现登录只作信息提示，不要求重新二选一或推荐 gh。存在 sources.local.md 时写明本机记录位置与读取规则，不将个人绝对路径写进共享正文。
4. CNB 单链接文件格式、GitHub Token/gh 的区别、未跟踪且实际忽略、Unix 权限/Windows ACL、禁止回显。不要把示例中的 Token 替换成真实值。
5. 按本次进程环境传递凭证的具体操作方法：读取当前值；CNB URL 必须含固定 cnb 用户和相同完整仓库；清空 helper 链，启用 useHttpPath，用仅响应 get 的短期 helper 精确匹配本次 URL，store/erase 不写；关提示与重定向。helper 忽略 `capability[]` / `wwwauth[]` 等合法多值元数据，仅对身份字段检查重复与匹配。环境结束即失效。来源缺失或鉴权失败停止，不能借用其他来源。完整契约从 [鉴权文档](authentication.md) 合并到项目正文，不能只引用本 Skill 安装路径。
6. 本次需要的 read/publish/sync 和 GitHub Issue 流程沿用相同来源规则；项目 Token 缺失、失效或权限不足时报告原来源并按用户明确决定处理，不回退全局 gh。说明推送前检查、逐 ref 结果回读、写入不明时只读核对的恢复方式。已有 PR/Release 脚本引用真实项目路径、输入与结果，不自动更换。
7. 普通 Git / IDE 默认沿用既有鉴权；有明确接入需求时按[鉴权文档](authentication.md#普通-git--ide-按需接入)记录实际 helper 路径、本机运行时、目标范围、共享 Worktree、来源记录、失败处理和验证结果。文件轮换直接读取当前值；不另存 Token。新设备或目录移动须重新设置本机接入。CI 仍须核对自己的环境和凭证，不把桌面验证扩大到 CI。

## 可选文档写入工具

node <skill>/scripts/git-setup/cli.mjs document-plan --project <根> --input -

输入 {path:"docs/agents/git-repository-operations.md",content:"经当前项目核对的完整说明",ruleFiles:["AGENTS.md","CLAUDE.md", "<已核实的WorkBuddy规则入口>"]}。省略 path 时使用上述默认路径；复用已有正文时显式传入原路径。实际入口按客户端检查结果给出，不凭示例创建无效文件。document-write 使用同一输入、--apply 和 --expected-fingerprint。

工具保留规则原文，在 git-setup:documentation 标记内替换引用；指向同一实体的规则只编辑一次。发现直接指向本正文的已有 Markdown 链接时保留原入口，不另加同主题块；Agent 必须核对其触发条件和强制读取要求，缺失时修改原句。间接必读引用、纯文本路径等由 Agent 沿实际规则核对并直接维护，不能为使用工具而增加重复入口。脚本不理解正文语义，文件写入完成不等于规则已生效。

写入前核对原文和链接，写后回读；部分失败报告已完成文件，不回滚覆盖后续用户内容。不保存例行事务、生成脚本、manifest 或运行包。分别从各宿主实际入口验证读取，报告已验证和未验证范围。

项目已有 docs-anchor 等映射时，沿其正式规则维护真实文档和现有引用。该工具拒绝经任意 symlink 路径写入，不可为绕过检查另建平行目录。

## 1.0.0 迁移：调用方迁移后删除旧实现

不再支持 0.4.x/0.5.x 的 harness-plan/apply/recover、auth-prepare/verify/cleanup、runtime-info、生成 run.mjs、gitsetup.auth-*.binding 或指纹运行包。没有转发别名、旧格式双读和回退。未发布的 CNB 多行方案也已撤回。

升级已有项目时先只读清点：实际配置中的 helper 引用及 reset 项、本机绑定键、规则中的旧入口引用、安装目录、所有脚本/Hook/CI 调用方和用户维护文件。旧安装检查只报告路径/键名，不输出鉴权值。按当前授权迁移调用方到项目文档或明确业务脚本，保留所需发布/同步/PR/Release 行为；验证之后，才删除确认属于旧实现的入口、绑定键及无人引用运行包。仅删除旧 helper 对应的精确配置项；没有证据不能删除其他 helper、全局配置或所有 .git/git-setup。

真实凭证不随源码升级转换、复制或清除。没有已授权真实项目迁移时只说明现状与待迁移对象；调用方无法迁移就报告具体阻塞，不静默保留兼容层。
