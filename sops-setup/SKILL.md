## SOPS Setup

用 SOPS 把配置值加密后存入 Git。age 公钥是加密接收者，解密需要对应的私钥。先定位用户指定的仓库及环境，再按任务范围检查、初始化或更新接收者。

### 检查 Skill 更新

Git 安装用原生 PowerShell 运行 `scripts/check_update.ps1`，或用 Bash 运行 `scripts/check_update.sh`。退出码 0 直接继续。退出码 10 时原样转述更新报告，用户同意后才传 `-Pull` 或 `--pull`。无法更新时说明原因并继续。用户未回应、拒绝或检查失败时按当前版本执行。

复制安装读取 [update.json](update.json)，只查询同一 Skill 稳定 tag 前缀。发现更新时报告本地版本、远端版本、仓库、tag、commit SHA 和安装目录。确认后按该 SHA 下载，验证名称、版本和简介前缀后整体替换。替换失败保留或恢复旧副本。宿主无法固定 SHA 或安全替换时继续使用当前版。用户要求关闭检查时，保留 `~/.config/sops-setup/.env` 中的其他设置，只设置 `AUTO_UPDATE_CHECK=0`，或让复制安装的检查逻辑读取同一开关。

### 找到项目的入口

1. 在用户指定目录定位实际 Git 根目录，确认环境和加密文件。先看项目的密钥说明、`.sops.yaml`、已知的加密文件路径及包装命令定义。检查时输出路径、接收者和状态即可。
2. 项目已有 `pnpm secrets` 或其他受维护的入口时，核对该入口的实际命令和脱敏行为，用它完成项目支持的操作。沿用当前的路径、文件格式和密钥来源。现有 KMS、PGP 或多密钥组规则按项目约定处理。
3. 直接用 SOPS 时，预检 `sops --version --disable-version-check` 和所需子命令。生成或核对 age 身份时另外验证 `age-keygen --version`。从实际运行环境确认工具路径、版本和权限。缺依赖时按系统选择官方安装来源。

### 按任务操作

- **检查或接入现有仓库**。检查配置及文件的加密状态。用户要求验证解密时，用项目已知的无输出探针，或从 [操作指引](references/setup.md#检查已有文件) 选用静默解密命令。以解密退出状态判断实际访问。失败时先区分文件格式、完整性和密钥来源或接收者不匹配。
- **初始化新仓库**。与用户已明确的环境和接收者对应。默认示例用不同的 age 身份分别加密开发和生产文件。按 [初始化](references/setup.md#初始化仓库) 写入公开规则和密文，验证所需身份可以各自解密，以及开发身份无法解密生产文件。接入旧项目时保留它已采用的格式和路径。
- **更新接收者或轮换**。先找出文件当前接收者与准备写入的规则。确定能解密的现有身份，再按 [更新接收者](references/setup.md#更新接收者与轮换) 更新实际密文。以新身份验证解密。撤销接收者时单独验证旧身份并判断是否需要轮换数据密钥和原业务凭证。

### 处理密钥与结果

- 私钥由项目授权的密钥文件、凭证库或部署端的 Secret 提供。只报告来源、状态和公开接收者。向 SOPS 或已确认的包装命令传递密钥时，使用文件引用、受控进程环境或文档定义的 stdin 入口，使私钥和业务明文避开聊天、工具输出、命令参数及 Git。
- 按现有授权处理生产配置。复用已指定的账号、凭证库条目和环境。只有需要用户解锁凭证库或授予访问权限时才暂停相关步骤。
- 交付时给出仓库、环境、改动的相对路径、接收者和验证结果。文件加密、解密成功和隔离验证分别判定。失败后先检查实际文件与配置，再从未完成的步骤继续。
