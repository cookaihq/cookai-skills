# frpc-launch

让 Claude Code、Codex 或 WorkBuddy 使用你已有的 FRP 服务，把本地网站或端口转发到公网，并检查、停止对应的本地进程。每个项目复用自己的连接选择、固定域名和代理，多个项目可以同时运行。

项目流程从 **1.4.0** 开始提供；安装后请让 Agent 核对实际版本。1.3.1 及更早版本不包含本版项目流程。

**1.5.0** 新增 Windows 原生客户端准备和进程管理。2026-11-01 验收：Windows 11 x64 合成测试 **153 通过、2 未执行**，Linux amd64 容器回归 **141 通过、12 跳过、2 未执行**；Codex 合成闭环通过，Claude Code 部分通过，WorkBuddy、真实 FRP 链路及 macOS 实机仍待验。具体范围见下文。

## 开始前准备

需要已有的自部署 FRPS、宝塔 FRPS 或樱花 FRP。Skill 管理本地客户端，不部署服务器，不修改远端 DNS、Nginx、证书或开机自启。首次保存连接只需 FRPS 地址、连接端口和 Token，本地服务端口到使用时再提供。

Windows 原生支持客户端下载、离线配置校验、隐藏后台启动、停止、状态与日志。实现面向 Windows 10/11、macOS/Linux 的 amd64/arm64；当前实测为 Windows 11 x64 的合成客户端生命周期及 Linux amd64 容器回归，macOS、Windows arm64 与独立 WSL 用户环境未复测。

真实客户端仍有独立缺项：官方 frp 0.70.1 Windows ZIP 被本机 Defender 拦截，未完成本机包哈希校验或执行；樱花客户端下载返回 HTTP 567，未完成真实登录。合成客户端测试不证明 FRPS、代理注册或公网业务可用。防护拦截时停止该分支并核查，不通过换目录、改名或关闭防护继续。

需要 uv ≥ 0.8，由 Agent 检查和准备锁定环境。首次运行可能下载 Python、依赖和 frpc；启动不会顺带升级已有 frpc。

## 完成首次配置

新连接默认保存当前项目，后续在该工作文件夹复用；个人全局连接保留为其他项目的默认，不同时改写两处。已有错误修复实际来源。

> 请帮我配置 frpc-launch。沿用已有管理方式，或让我选择在本机填写配置 / 从 secret-book 选择并保存。新连接保存当前项目，保留个人全局默认；现在只保存连接，使用时再提供本地端口。告诉我写入位置和实际来源，隐藏 Token。

自行填写时，由 Agent 指明当前项目 `.env.local` 的位置，不需要把完整 Token 发到对话里。Git 工作树内的文件必须未跟踪且被忽略；程序拒绝不安全目标。secret-book 是可选途径，后续业务直接读本机，表中轮换不会自动同步。

连接字段为 `FRPC_LAUNCH_SERVER_ADDR`、`FRPC_LAUNCH_SERVER_PORT`、`FRPC_LAUNCH_TOKEN`，三项为一组。换服务器时只提供地址还不够，Agent 会补问端口和 Token，不从另一套默认借用凭证。

域名后缀来自本机 `FRPC_LAUNCH_DOMAIN_SUFFIX`。例如后缀为 `dev.example.com`、项目名为 `my-app`，首次候选为 `my-app.dev.example.com`。确定后固定保存，不随默认后缀变化改名。本机同名项目获得稳定的区分后缀；远端占用、DNS、证书仍需核实。

## 第一次使用

启动会把所选服务通过已有入口公开，并留下后台进程。先启动应用，再在**该项目工作文件夹**对 Agent 说：

> 使用 frpc-launch，把这个项目的 3000 端口透传出去。优先用本次明确提供的连接，其次用项目保存，最后用个人全局默认；复用项目固定域名。核对已有路由和本地服务后启动，给我完整访问地址和各层验证结果。

之后不必重复提供域名。首次域名或路由未知时，Agent 会说明缺项。HTTPS 在 Nginx 解密后转给 frps HTTP 入口时，代理仍保持 HTTP；连接 frps 的端口不等于网站访问端口。

预期得到完整 URL，以及本地服务、FRP 登录、每条代理、公网响应和业务状态。公网 200 可能是准备页，进程或登录成功不能代替业务验收。

## 常用请求

- “把当前项目改到 4000 端口，域名和其他路径不变。”——定点更新；运行中先说明变化，按重启授权只重启该项目。
- “把这个域名的 `/api/` 转到 8081，保留其他路由。”——核对路径语义，保留其他代理和高级选项。
- “检查这个项目的连接来源、进程和完整公网 URL。”——各层分别报告，不回显 Token。
- “停止项目 A 的 FRP，项目 B 继续运行。”——按 A 的身份停止，不停止 B 或本地应用。
- “刚才会话中断了，检查这个项目是否还在转发。”——读取落盘身份和日志，继续检查或停止，不重复拉起。

## 配置从哪里读取

工作文件夹是本次处理的项目目录，由 Agent 显式指定；不是 Skill 安装目录，也不向父目录搜索。

| 顺序 | 来源 | 行为 |
| --- | --- | --- |
| 1 | 本次明确提供的完整连接 | 保存时优先，按已授权的项目范围保存 |
| 2 | 运行程序的环境变量 | 当前进程设置；新连接须先保存才能用于项目启动 |
| 3 | 项目 `.env.frpc-launch` | 优先的项目专用文件 |
| 4 | 项目 `.env.local` | 新连接默认保存位置 |
| 5 | 项目 `.env` | 项目已有配置 |
| 6 | 个人 `.config/frpc-launch/.env` | 自动回退的个人默认 |
| 7 | 个人 `.config/frpc-launch/frpc.toml` | 从同一文件读取完整 `serverAddr/serverPort/auth.token` 连接组 |

三项连接整组选择；高层只填半组会报缺项，不跨层拼接。普通独立选项按首个非空值读取，例如域名后缀和二进制位置。没有项目连接时使用个人默认，结果标明“使用了全局连接”；读取不会自动把全局 Token 复制到项目。

域名和代理保存在 `.frpc-launch/project.toml`。运行文件、PID、脱敏日志位于个人受管目录的 `projects/<项目标识>/run/`，Agent 会报告完整路径。项目使用独立代理名与进程身份；Token 只存项目 `.env.local`，运行文件使用环境模板，不再保存一份全局副本。

| 环境 | 个人配置与运行目录 |
| --- | --- |
| macOS / Linux | 当前运行用户的 `~/.config/frpc-launch/`；个人文件夹通常为 `/Users/<用户名>/` 或 `/home/<用户名>/` |
| Windows 原生 | 当前 Windows 用户的 `%USERPROFILE%\.config\frpc-launch\`；客户端与项目运行文件使用此位置 |
| WSL | WSL Linux 用户的 `~/.config/frpc-launch/`；与 Windows 用户目录分开，不自动互读 |

已有完整原生 TOML 与专用受管目录可继续按原接口使用，不会自动迁移成项目模式。让 Agent 先核对现有调用方式；原生完整配置生成器会覆盖文件，已有配置应定点编辑。

## 遇到问题时

> 请检查 frpc-launch 的实际版本、项目目录、各项来源和是否已填写，隐藏 Token。新设置被高优先级文件遮蔽时指出实际来源，不要另写全局文件。沿我的完整 URL 核对域名、证书、代理和本地同路径的内容。

域名占用时先核对具体项目和远端代理，DNS 能解析不等于可用。公网显示准备页时检查应用是否加载配置。启动等待超时会保留可识别的进程记录，先核对日志和现状再决定下一步。

Windows 上可以说：“请准备并验证原生 frpc 客户端，先做离线配置校验，再按当前项目启动并检查日志。”遇到“拒绝访问”，让 Agent 区分 uv、客户端、配置目录和私有文件权限。不同宿主可能使用不同 Windows 执行账号；私有配置不会自动向另一账号开放，应沿宿主正常授权流程处理。不要自动放宽配置权限或关闭沙箱。

## 更新

Skill 默认自动检查更新，只提醒；实际更新需逐次确认。Git 检出使用随包适配器，复制安装按稳定 tag 和精确提交替换。缺少已核实的宿主更新能力时明确报告并继续任务；检查失败不等于已是最新。

可以说“关闭 frpc-launch 的自动检查更新”。`AUTO_UPDATE_CHECK=0` 只读取个人 `.config/frpc-launch/.env`，不读取项目文件。更新 Skill 与升级 frpc 二进制是两件事。下载校验只保证完整性，不等于发布者签名验证。
