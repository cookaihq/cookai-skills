# 规则咨询与结果追溯

用户询问处理方式时，先看所指材料、页或区域和关注的关系，再读内容规则索引及命中的正文。已有问题清楚就直接核对；只有歧义会改变匹配结论才澄清。答复区分完整覆盖、部分覆盖、无匹配规则、证据不足，并给规则 ID、适用条件和边界。咨询本身不启动转换或修改规则。

用户指出某个输出有误时：

1. 从已给任务目录或结果路径定位该任务。读 README、task.json，再读相关 events.jsonl、结果 provenance.json 和页记录。不要检索所有项目，也不凭“最后一次任务”猜位置。
2. 核对 source/document.pdf 的身份及物理页，读取实际 run 的 snapshots 和问题截图；解释记录能证明的实际动作、采用条款及版本、输出对应区域和已知疑点。页记录中的行范围定位页 Markdown；整份结果额外提供页起始行。规则与证据的相对路径以任务根为基准。
3. 对照源页和用户指出的差异，再判断是执行未遵守已有规则、规则边界不足、新内容类型、清洗偏好，还是证据不足。当前规则与历史快照分别说明。
4. 需要纠错且用户已经要求时，在同任务 `resume --redo-pages ...` 并保留历史版本；只有规则含糊、冲突或确有可复用新关系才提出改规则。忠实结果满足原文、用户只想删内容时走清洗。

记录缺失或不足时明确哪些历史事实无法核实。现有源页和当前规则可以支持当前分析，不能反推当时一定如何执行；缺记录也不证明当时没有规则。不要补写未经观察的旧事件。源内容不同要另建关联任务。

修改规则时沿用五个连贯主题与八项结构：适用依据、保留关系、动作、反例、配合、疑点处理、样本预期、检查点。条款 ID 保持稳定；行为变化随 Skill 升版，旧任务保留原快照。缺少实际反例时明确缺口，假设案例不算实测。
