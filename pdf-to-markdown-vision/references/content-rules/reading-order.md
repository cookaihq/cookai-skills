# 阅读顺序与图文关联

规则 ID：`reading-order`。行为版本随 SKILL.md 的 metadata.version。以下样本是规则依据；不是每次转换的固定分支，也不是对任意文档的质量保证。

1. **适用与依据：** 页面有多栏、跨栏标题、正文旁配图、同小节独立表格或相邻列表。结合标题、图注、条目内容及上下文确定归属；无标题列表也可能独立，例如目录的条目/页码与产品参数分别成组。底色、边框和留白只作辅助，不能单独证明主题改变。
2. **保留关系：** 章节、段落和步骤顺序，图片/表格与其解释和小节的联系，以及列表内部的同组关系和独立列表之间的边界。保留全部文字、数字、单位及条目次序；物理页跨印刷页时保留两套页码定位。
3. **处理：** 按语义阅读顺序组织 Markdown。RTC 控制面板小节使用“标题 → 完整控制图 → 功能表”；ZNH 的不同主题分别成组，图的归属结合标题、图注和语义判断。列表按以下方式表达：
   - 先判断同一列表的延续还是独立列表。独立列表分别写有序文字区域，在 `reason` 中记录语义依据；同一列表即使因排版分成多个区域，也保持相同列表标记和编号延续。
   - 相邻同型列表之间只有源码空行时，CommonMark 仍可能将其合并。无标题且需独立的两个列表，保留一个源码空行，并让后一个列表使用不同的同类标记：无序列表交替用 `-` 与 `*`；有序列表交替用 `1.` 与 `1)` 的分隔符，数字沿用原文。只改变相邻列表的同层标记，不改变内容、嵌套层次或编号。这使渲染产生两个列表，组间显示一行留白。
   - 已有原文标题、正文或列表类型变化已能分隔时，沿用现有边界。无需再加分隔；不补造标题、解释、水平线或背景，也不使用原始 HTML。
4. **反例：** 空间距离最近的段落未必解释该图；不得把另一栏或下一小节拼入当前主题，也不把物理第 10 页直接当作仅有印刷第 10 页。同一语义列表内的普通留白、装饰底色、条目换行或跨栏延续不构成独立列表，不为这些外观变化切换列表标记。
5. **配合：** `visual-unit` 决定完整裁图及图内文字的表达；本规则保留原始图注和独立正文/表格的阅读位置与归属。图内标题/轴标不误作新的正文段落，原始图注也不误作可省去的标签副本。表格及公式规则负责各独立内容。
6. **不确定处理：** 补看相关标题、图注、列表首尾及相邻区域，核对条目是否具有共同主题或连续编号。仍不能确认列表归属时保留该源区域和阻塞疑点，不猜定拆分或合并，也不自造解释性标题消除歧义；其余独立区域可继续。
7. **样本与预期：** RTC 用户第 19 页；ZNH 物理第 2、8、10 页，分别保持跨栏引言、独立主题及印刷第 10–11 页三步指引。MXO 3 物理/印刷第 3 页的目录与蓝底五条参数是独立列表：目录末项后显示一行留白，五条参数仍为一组，原字词、单位和次序保留。用于解释边界的合成反例：同一参数列表跨普通留白、装饰底色及条目换行仍是一个列表；两组已有原文标题时不再增加分隔。这些合成反例不是原件观察证据。
8. **检查：** 对照源页核对正文、图注及列表条目不遗漏、不重复，主题归属、小节边界和步骤次序正确。检查组装后的未清洗、清洗及最终 Markdown 的实际渲染：独立列表生成两个列表且显示一行组间留白，同组条目仍连续，已有标题处没有重复空隔。源码空行或页 JSON 分成两个区域不能代替显示检查；同时核对来源行号映射。RTC 后续小节及 ZNH 另一主题为既有边界案例；RTC 完整原件共 371 页，功能表中的控制项与单元格列表须保持对应。
