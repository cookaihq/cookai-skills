# 完整视觉单元与图片理解

规则 ID：`visual-unit`。行为版本随 SKILL.md 的 metadata.version。以下样本是规则依据；不是每次转换的固定分支，也不是对任意文档的质量保证。

1. **适用与依据：** 照片、软件或频谱截图、流程图、接线图及带文字示意图，主体、标注和连线依靠空间位置表达关系。先实际看图，按内容作用识别配图，不能只凭 PDF 将内容存成位图就套用本规则。
2. **保留关系：** 完整保存视觉主体及相关文字、箭头、连线、图例和接口，保持与源图注、正文及小节的关联。图片内部文字不强制逐字转写；可辨信息可用于理解，不把全量标签、编号、数值或菜单改抄到 `alt`。
3. **处理：** 完整裁图并以简短、忠实的 `alt` 标识可见对象。源图注写在 `markdown`，保持原文字面内容并留在解释块外；没有源图注或独立原文时可为 `""`。根据实际可观察对象、关系或用途，用 `image_understanding` 写可靠的解释正文，不猜测参数或技术结论。程序在图及源图注附近生成标准 Markdown 引用块，标题固定为 `图片理解`，不加“AI 生成”；标题与说明间为引用空行 `>`，每行说明属于同一块。块前后各有至少一个完全空白、不带 `>` 的空行，文件末尾同样保留结束空行。
4. **反例：** 正文、标题、源图注、独立表格、公式和技术条件仍须准确转写，影响准确性的疑点继续阻塞。整页扫描的正文或表格即使为位图，也不能当作配图跳过。图旁正文不并入图片理解；解释不能冒充原文，缺图、裁错和损坏资源不能算正常完成。
5. **配合：** 先用 `reading-order` 确定图内文字与独立原文的边界及阅读顺序；独立表格使用 `table-groups` / `merged-conditions`，公式使用 `formulas`。本规则属于内容转换，不由是否清洗决定。清洗按选定用途删改，默认保留图片、原图注和理解块边界，并保持源文与解释的来源区分。FPL1000 两页分别保存，不自动拼接。
6. **不确定处理：** 图内小字无法可靠辨认时不猜写，不单独因此阻塞；整体含义也无法可靠理解时保留原图，省略 `image_understanding` 或传空字符串，整个空块随之省略，不写占位说明、不因此阻塞。可在处理记录的 `reason` / `review` 说明原因。裁图边界不明则补看源页，缺失或裁错仍须修复。正文等反例的疑点按通用补查、证据和阻塞规则处理。
7. **样本与预期：** 城市空中交通手册物理第 6 页 Sky View、第 7 页实时频谱截图保留完整图片、正文和源图注；图内经纬度小数、重叠编号或细小测量值不强制抄录，不因此产生 partial。可靠理解说明实际界面对象及可观察关系；不依赖不可辨小字推导结论。流程/接线/带标注示意图采用同样边界。整体不可理解配图只保留图片；扫描正文、独立表格和模糊公式为必须转写或阻塞的反例。既有 FPL1000/ZNH 完整标注图仍保留图片及归属，但不再要求逐项图内转写。
8. **检查：** 工具检查图片真实存在、引用可达、引用块的实际 CommonMark 边界与末尾空行、输出行及来源关联；Agent 对照源页检查裁图完整、图文归属正确、解释有可观察依据且无猜写，正文/表格/公式未借配图豁免。无可靠理解时无空块或占位；清洗与不清洗结果均可分别追溯源文和图片理解。工具通过不代替实际看图。

```markdown
![GNSS模拟软件的天空视图](assets/p0006-sky-view.png)

> **图片理解**
>
> 右侧圆形视图区呈现卫星在天空中的分布，标记颜色与左侧图例对应；左侧显示状态信息。

后续原文。
```
