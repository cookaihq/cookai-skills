# PDF 视觉转 Markdown

## 入口与分工

显式选中本 Skill 后，单独的本地 PDF 路径或 PDF 直链就是转换请求。未给页范围处理全文；未选清洗方案采用有效项目默认，没有默认则保留原文。沿用已选项目根；只有项目归属确实不明才澄清。PDF 所在目录、当前子目录和 Skill 安装目录都不代替已选项目根。

宿主负责看图、阅读顺序、语义转写、清洗和内容核验；随包程序只处理文件、渲染、裁图、记录与机械检查。使用宿主的原生看图工具。没有看图能力就报告前提缺失；文字层仅作辅助，不调用外部 PDF 转换服务或独立视觉模型。

先按用户意图分支：

- 转换、续跑、补页或纠错：执行下方转换步骤。
- 建立、修改或选择清洗方案：读取 [清洗与配置](references/cleaning.md)，按本次或长期作用范围处理。
- 询问规则或反馈具体结果：读取 [规则咨询与结果追溯](references/diagnosis.md)，先解释可核实记录；咨询本身不触发转换或改规则。

## 0. 自动检查更新

Windows 原生执行 `scripts/check_update.ps1`；macOS/Bash 执行 `scripts/check_update.sh`。退出 0 继续，不复述例行输出；退出 10 原样转述更新报告，用户同意才分别用 `-Pull` / `--pull` 应用。未回应、拒绝或检查失败都按当前版继续。复制安装按 [更新协议](references/update.md) 查询固定 tag 与 commit。关闭检查只写个人目录 `.config/pdf-to-markdown-vision/.env` 中的 `AUTO_UPDATE_CHECK=0`。

## 转换步骤

1. 读取 [工作流与文件契约](references/workflow.md)。按本机 Shell 调用 `uv run --frozen --project <Skill实体目录> <Skill实体目录>/scripts/workflow.py ...`。批量每个 PDF 一项任务，默认串行；仅明确要求时并行不同任务。
2. 以 `start` 保存原件、确定物理页范围和规则/清洗快照。本次非清洗转换要求（如公式改为纯文本）先写文件并传 `--requirements` 保存实际内容。记录返回的任务目录与 writer。任务恢复用 `resume`，读取该轮 `requirements.json`，沿用明确任务及其要求；同版本核对有效进度，升级后全部目标页按当前版重新处理。启动返回清洗错误时可继续未清洗转换，必须说明选定清洗尚未完成。
3. 对每个待处理页 `render`，用宿主看图工具实际打开返回的图。按 [内容规则索引](references/content-rules/index.md) 选择并读取命中的规则，首次看图同时确定区域、顺序和转写。按页推进，不一次载入整本高清图。
4. 按文件契约写页 JSON：有序区域、归一化坐标、正文、真实图片需要、规则 ID、简短采用依据及核验事实。完整视觉单元保留所有标签和连线，并在图下转写可辨认文字；邻近正文已有同样文字时保留关联、避免额外文字副本。公式默认 LaTeX，用户明确接收系统不支持数学渲染时用无歧义括号文本。
5. 针对疑点最多追加两次局部放大（默认 180 dpi，补查 300 dpi），记录原因。仍不清楚则保留区域证据及阻塞疑点，不猜写。用 `submit-page` 保存，实际打开生成的裁图确认边界、标注和清晰度；裁图有误修订本页。页失败用 `fail-page` 记录并继续其他独立页。空间不足暂停新增处理。
6. 选定清洗时读取 [清洗与配置](references/cleaning.md)，按快照从未清洗结果生成清洗结果并记录变化。普通重洗复用有效未清洗页；改变识别或裁图时重做相关页。无清洗要求保留全部原文，包括重复页眉、脚注、安全提示和表头。
7. 用 `finish` 检查、组装并交付。只有完整且无阻塞疑点的结果自动采用；阶段结果列明缺口。打开交付 Markdown，核对关键数字、单位、公式、表格条件、图文归属及实际图片。返回 Markdown、图片目录、任务 README 的可访问文件链接，说明完成/失败/待复核范围、耗时和可获取用量；未知用量写“无法测量”。正常完成由程序清理可再生缓存，失败/中断保留。

每轮使用同一 writer，结束或主动中断调用 `finish` / `pause` 释放归属。占用冲突读取返回的 owner 和接续信息；确认原执行者已停止才显式接管。同任务只支持单设备单写入者。
