# AS · Agent 会话启动器

在 Orca 的当前项目和分支中，新开一个 Agent 会话。你可以保存每个 Agent 的默认模型与思考强度，用短代码选择预设，并自动发送首条消息；加上 `-r`，让新会话先读取当前会话的原始记录再接手。

当前版本 **[1.1.0](https://github.com/cookaihq/cookai-skills/releases/tag/as%2Fv1.1.0)**，包含常用配置初始化、默认值快捷采用、调用解析与原始记录交接。Windows Codex 默认沙箱的完整启动验收仍受访问限制阻塞，macOS 尚待实机验收，具体范围见下文。

## 开始前

需要正在运行的 Orca、已在 Orca 打开的当前工作目录，以及本机可用的 Codex 或 Claude Code。Agent 会协助检查 Git、uv 和运行环境。模型与强度选项来自本机 Agent 的模型目录；Orca 使用的账号可能不同，实际启动结果仍以 Orca 回执为准。

AS 可以从以下宿主显式调用。当前可启动的目标是 **Codex、Claude Code**；WorkBuddy 可以调用指向这两个目标的预设，当前不提供启动 WorkBuddy 会话的默认值。

| 调用宿主 | 安装与显式入口 | 验证范围 |
| --- | --- | --- |
| Codex | 当前用户的 `.agents/skills/as`，输入 `$as` | 必需实测宿主；本机验收进度见下文 |
| Claude Code | 当前用户的 `.claude/skills/as`，输入 `/as` | 原生显式字段已适配；未做此宿主的 Skill 调用实测 |
| WorkBuddy | 通过客户端本地技能入口导入完整 `as` 目录，并明确选中该技能 | 5.9.3 客户端的显式调用字段已核对；未做 Skill 调用实测 |

Windows 原生环境已执行脚本、浏览器与 Orca 业务验证，包含 Codex → Claude 的原始记录交接，以及 Codex 读取后等待的无正文调用。Codex 默认沙箱已通过项目原生入口加载本版并读取自己的原始会话；完整业务验收仍受 Orca 运行元数据访问拒绝、Claude 模型目录查询超时阻塞。需要通过宿主正常授权机制解决访问与目录查询后再验收。macOS 尚待实机验收。WSL、原生 Linux 和远端 Orca 路由尚未验收。

初始化接入已通过 52 项 Python 回归、页面事件、真实浏览器和独立安装测试。Codex 默认沙箱实际验证了缺项提示、只补当前 Agent 默认值及回读；后续启动仍在 Orca 元数据访问处失败，尚未完成这一功能的宿主业务闭环。

## 让 Agent 帮你安装

把下面整段发给准备使用 AS 的 Agent。仓库中有多个 Skill，只安装 `as`，保留其完整配套目录。

```text
请从 https://github.com/cookaihq/cookai-skills 的 as/v1.1.0 版本安装 as Skill，只安装仓库中的 as 目录及其配套文件；GitHub 因网络原因不可达时，自动尝试 https://cnb.cool/zhidateam/tannt/tannt-skills 的相同版本与目录，并说明实际来源。沿用当前宿主的原生技能安装入口，保留已有配置，检查 Orca、目标 Agent 和运行环境，验证技能能被发现并告诉我显式调用方式。安装验证先停在配置与调用预览，不创建会话。
```

## 完成首次配置

对 Agent 说：

```text
请使用 as 打开当前项目的配置页，让我选择默认模型、思考强度和会话预设。使用 AS 独立的个人全局配置，保留已有设置，告诉我保存位置。
```

配置为空时，页面提供一次性的“添加常用配置”：两套 Agent 默认配置和四套会话预设。添加后可修改或移除不可用的组合，点击“保存配置”才生效。添加、关闭提示或已有任意配置后，都不再重复推荐；仅关闭网页仍可下次决定。默认配置与预设独立编辑，升级不替换个人选择。“调用试用”只展示解析结果，不会创建会话。AS 不需要单独填写 API 密钥，使用已有的 Agent 和 Orca 登录环境。

配置页空闲 60 分钟后到期，点击、输入和滚动会续期。页面关闭或到期后，可再次请求“请重新打开 AS 配置页”。手机或其他设备访问需要 FRP 或 Tailscale，默认链接只供本机使用。

### 配置保存在哪里

默认每次显式调用都读取个人全局 `config.json`；不会读取其他 Skill 的设置、项目 `.env` 或向父目录查找。默认值与预设各自保存为完整记录，不跨记录补齐字段。缺少当前 Agent 默认值时，Agent 会展示推荐模型、强度和保存位置，让你选择“采用推荐值并保存后继续”或“打开配置页自行设置”。快捷采用只补当前 Agent，保存并回读成功后接续原调用；模型不可用或保存失败时停止，不换用其他组合。

| 运行环境 | 默认配置位置 |
| --- | --- |
| Windows 原生 | 当前 Windows 用户个人文件夹下的 `.config\as\config.json`，例如 `C:\Users\你的用户名\.config\as\config.json` |
| macOS / Linux | 当前进程用户个人文件夹下的 `.config/as/config.json`；macOS 通常为 `/Users/你的用户名/.config/as/config.json`，Linux 通常为 `/home/你的用户名/.config/as/config.json`；尚未实机验收 |
| WSL | WSL 用户自己的 `.config/as/config.json`，不自动读取 Windows 用户文件；尚未验收 |

用户明确指定独立测试或其他配置文件时，只读取该文件，不与个人全局配置合并。工作文件夹是调用时所在目录，决定新会话的位置，不决定默认配置文件的位置。当前目录必须与 Orca 打开的工作区根目录一致；不匹配时会停止并说明原因。

一次性提示的处理状态保存在同目录的 `config.json.initialization.json`；独立配置使用对应文件名。它跨项目和浏览器生效，删除个人预设或升级不会恢复提示，目前不跨电脑同步。

要确认实际来源，可以说：“请使用 as 查看当前默认值和预设，告诉我工作目录、配置路径及缺项，不创建会话。”保存成功只说明配置通过本地校验，不代表新会话已启动。

## 第一次使用

保存当前 Agent 的默认值后，在 Orca 对应项目的会话中输入：

```text
$as
```

这会创建一个空白新会话，使用当前 Agent 保存的默认模型与强度。Claude Code 使用 `/as`；WorkBuddy 先显式选择 AS，再指定已有预设。

也可以直接在后面写首条消息。新会话收到正文后会开始处理，费用按其账号与模型规则产生：

```text
$as 打开as的设置页面
```

这会使用当前 Agent 的默认配置新建会话，把“打开as的设置页面”交给新会话。若要留在当前会话打开设置页，说“请用 as 打开当前项目的配置页”，不加 `$as` 命令前缀。

要跨 Agent 使用预设，在配置页保存一个代码，例如 `a`：

```text
$as a 请检查当前项目的 README，先回复你看到的项目名称。

暂时只读文件，不修改代码。
```

正文的内部空格和换行会保留。不带 `-r` 时只传本次正文，没有正文打开空白会话。AS 返回目标 Agent、模型、强度、目录及启动回执；“消息已交付”不表示正文任务已经完成。

### 带上当前会话上下文

在同一台电脑上，使用已保存的预设 `a`：

```text
$as a -r
```

新会话会收到当前会话原始记录的路径和固定读取范围，自行读取后确认接收、等待你的下一条指令。来源和目标可以是不同 Agent；也可以用 `$as -r` 选择当前 Agent 的默认配置。要让接收方读取后立即处理任务，可以写：

```text
$as a -r 继续实现刚才确认的方案
```

`-r` 放在预设前后都可以，须位于消息正文之前。需要把 `-r` 本身作为消息时，用 `$as a -- -r`。

交接直接读取原文件，不预先生成摘要，也不会把旧消息导入新会话的聊天界面。读取范围固定在启动时，原会话之后的追加不混入；超长记录会分段读取，仍受接收方的上下文窗口限制。图片等附件需另行核对。请保留原始记录和 AS 的调用记录，直到接收方读完。

接收方必须能访问同一台电脑上的文件。来源身份不明确、文件不可读或格式不支持时，AS 会说明具体缺项，不悄悄启动空白会话。当前支持 Codex JSONL、Claude Code JSONL 和 WorkBuddy 的 `.codebuddy/projects` 消息记录；Claude Code / WorkBuddy 需要宿主提供准确当前会话 ID，其他 WorkBuddy 存储形态尚未适配。跨电脑、Windows 与 WSL 之间不能仅靠传路径完成交接。

首词命中已保存的代码时使用预设。未知词后紧接 `-r`（例如 `$as wrong -r`）会报告预设不存在；后接普通正文（例如 `$as wrong 提示词 -r`）则完整保留为正文。严格选择预设可用 `$as --preset a 正文`。要发送字面 `wrong -r`，或正文恰好以已有代码开头，用 `$as -- 正文` 明确正文边界。

从 1.0.0 升级无需修改配置；原有已保存代码的用法继续有效。未知首词按上面的固定语法判断，AS 不猜测或自动纠正预设代码。

权限和 Chat / CLI 界面模式沿用 Orca 的启动配置。AS 不承诺复制当前会话中临时修改过的全部参数。

## 遇到问题时

| 现象 | 对 Agent 说 |
| --- | --- |
| 还没有默认值、想修改预设 | “请使用 as 打开配置页，保留现有配置。” |
| 模型或强度不可用 | “请使用 as 刷新真实模型目录，核对该预设和 Orca 实际使用的账号。” |
| 文件或程序访问被拒绝 | “请检查 AS 报错路径和当前宿主权限，按宿主正常授权流程修复，保留我的配置。” |
| 启动超时或没有看到会话 | “请使用 as 核对刚才调用的原始记录和 Orca 会话，不另建会话，也不重发正文。” |
| `-r` 提示找不到来源或读不到记录 | “请检查当前会话的准确 ID、原始记录路径和接收方读取权限，保留原始文件，不创建空白替代会话。” |
| 页面提示配置被其他程序修改 | “请保留我的草稿，帮我比较磁盘配置，再重新载入。” |

AS 保存调用记录以核对与恢复。运行记录默认在个人配置旁的 `runtime` 目录，包含首条消息和精确启动参数，仅供本机恢复使用。结果不明时先核对原操作；只有取得 Orca 原生操作标识时才重放同一操作，不能换一个标识重复启动。

## 更新

显式使用时自动检查更新；检查失败可以继续当前任务。发现新版本会说明版本与变更，经你确认才更新。复制安装使用 AS 自己的 `as/v` 版本，不使用多 Skill 仓的通用“最新 Release”。

可以说：“请关闭 AS 的自动更新检查。”开关单独位于个人用户目录 `.config/as/.env` 的 `AUTO_UPDATE_CHECK`，不参与业务配置读取。Windows 原生使用 PowerShell 更新入口，macOS 使用 Bash；二者读取各自运行环境的用户文件夹。更新保留安装目录之外的个人配置。
