# 运行入口

以下参数接在 `uv run --frozen --project <Skill目录> python <Skill目录>/scripts/as.py` 后。保持用户调用时的目录，路径作为独立参数；正文通过 UTF-8 文件读取，不拼接 Shell 命令。

| 命令 | 作用 |
| --- | --- |
| `catalog` | 只读查询本机 Codex、Claude 原生模型目录；不发用户消息 |
| `config` | 读取 AS 当前配置、修订号和准确来源；缺文件返回空配置，不写演示数据 |
| `ui start` / `ui status` / `ui stop` | 启动、查询、停止同归属配置页面 |
| `resolve --current-agent codex --input-file <文件>` | 只解析调用与配置，不创建会话 |
| `launch --current-agent codex --input-file <文件> --request-id <唯一ID>` | 核对目录、模型和配置并启动一次 |
| 原 `launch` 命令加 `--adopt-recommended-default` | 用户明确选择已展示的推荐值后，只补当前 Agent 默认值并继续原请求；没有先前缺项回执时拒绝 |
| `inspect --request-id <原ID>` | 查看原调用回执，不重新发送 |
| `resume --request-id <原ID>` | 使用原始 argv、目录和 operationId 恢复原操作 |
| `context-source --current-agent <来源Agent>` | 只读定位当前会话原始文件，核对身份和完整记录范围 |
| `context-read --record-file <launch记录> --cursor 0:0` | 接收方分页读取固定范围；沿用返回的 `next_cursor`，直到 `complete=true` |

顶层 `--config-file <绝对路径>` 用于明确选择的独立配置或合成测试；它不改变默认全局配置，也不跨文件补齐字段。`--runtime-dir <路径>` 用于相应私有运行材料，测试时使用项目已忽略的任务临时目录，例如 `tmp/as/`。它们位于子命令之前。UI 的 `--public-origin` 只在已配置 FRP/Tailscale 后使用；`--idle-seconds` 仅供短期限验收。

## 调用文本

以下内容写入 `--input-file`，由 `resolve`、`launch` 和配置页调用预览按相同规则解析。Claude Code 把 `$as` 换为 `/as`。

| 调用 | 选择与首条消息 |
| --- | --- |
| `$as` | 当前 Agent 默认值，空白会话 |
| `$as 打开as的设置页面` | 当前 Agent 默认值；发送 `打开as的设置页面` |
| `$as Please review README` | 未命中已保存代码时使用默认值，发送全部正文 |
| `$as a 正文` | 首词 `a` 是已保存代码时选择该预设，发送代码后的正文；否则整段作为默认会话正文 |
| `$as --preset a 正文` | 明确选择预设 `a`；代码缺失或不存在即报错，不创建会话 |
| `$as -- a 是正文的第一个词` | 明确使用默认值，发送 `a 是正文的第一个词`，即使存在预设 `a` |
| `$as a -r` / `$as -r a` | 预设 `a`；交付原始记录读取指令，读取后等待用户 |
| `$as -r` | 默认配置；交付当前会话的原始记录读取指令 |
| `$as a -r 继续检查` | 预设 `a`；先读取原始记录，再处理 `继续检查` |
| `$as a -- -r` | 预设 `a`；只发送字面正文 `-r` |
| `$as wrong -r` | `wrong` 未保存时返回预设错误，优先于默认配置缺项 |
| `$as wrong 提示词 -r` | 未命中代码，整段作为默认会话正文 |
| `$as -- wrong -r` | 使用默认配置，发送字面正文 `wrong -r` |

只移除命令前缀、已选预设/控制参数及它们与正文之间的分隔符；换行分隔时移除一个换行，正文自己的缩进、空行、CRLF、尾随空格和字面字符保留。参数只在正文开始前解析；`-r` 可放在预设前后，`--` 结束参数解析。正文内部的同名文字保持原样。没有 `-r` 的全空白正文打开空会话；有 `-r` 则交付读取指令并等待。

`launch` 和 `context-source` 支持 `--source-session-id`、`--source-file`；来源是当前调用者，不能从目标预设倒推。来源定位、读取范围和恢复见[原始记录交接](context.md)。`context-read` 的 `--include-tools` 按需包含工具证据，`--max-chars` 控制页面大小；此命令不启动 Agent，也不写源文件。

从 1.0.0 升级：已保存代码的简写和配置文件继续使用；未命中的首词后紧接 `-r` 时报告未知预设，后接普通文字或独立出现时属于正文。显式严格选择使用 `--preset <代码>`。只有定义过的 `-r` 参与候选前瞻；`--` 为正文边界，其他以连字符开头的文字不自动成为参数。启动正文即使提到配置也交给新会话；当前会话管理配置的入口见 `SKILL.md`。

## 配置、模型与运行状态

结构为 `{"defaults":{"codex":{"model":"实际ID","effort":"实际强度"}},"presets":{"a":{"name":"名称","agent":"claude","model":"实际ID","effort":"实际强度"}}}`。模型不支持强度时保存 `null`，启动不传 `--effort`。默认值与预设均为完整记录，无跨记录继承。界面一次保存整份文件，校验失败不部分写入；OS 文件锁协调同协议写入，修订号检测外部变更，不保证不参与锁的外部写入者在最终检查后的原子性。

模型来自 Codex `app-server` 的 `model/list` 和 Claude stream-json `list_models` 控制查询，与 Orca 的模型发现协议一致。只保存明确的实际 ID；页面不把原型演示值或 CLI 示例当目录。每次启动重新发现；保存时重查发生变化的选项。目录来自本机 CLI 的当前登录与环境；Orca 管理的账号可能不同，最终能力以 Orca 启动回执为准。

Orca 选择沿用 `orca-cli` 约定：显式 `ORCA_CLI_COMMAND`，其次开发环境 `orca-dev`，否则 Windows/macOS `orca`；Linux 非托管终端使用 `orca-ide`。只选择一次，不自动切换生产/开发实例。当前实现从本机 Orca 查询当前工作区并使用返回的精确 address；不根据 `host` 推导远端路由。目录不等于工作区根时停止，避免悄悄在父目录启动。远端配对及原生 Linux/WSL 尚未验收。

运行材料默认在 `.config/as/runtime/`。`as.log` 与 UI `service.log` 记录操作 ID、状态和错误类型，轮转限制为 1 MiB × 3；不打印首条消息。`launches/<request-id>.json` 为私有恢复记录，含精确 argv 和首条消息，不用于公开日志；不自动删除尚需恢复的操作。`inspect` 返回回执与目标。退出码 0 为正常结果，1 为明确的本地/配置错误，2 为启动结果尚未确认。

UI 启停身份由安装路径、项目目录、配置文件路径及独立运行目录绑定。保存配置不会自动启动会话。仍在等待的 Agent 应核对原调用、目录与配置，再接续已授权任务；结束的会话由用户重新显式调用。

初始化提示状态与业务配置分离，保存到配置文件同目录的 `<配置文件名>.initialization.json`。页面负责结束提示；`config` 和 `resolve` 仍只读。该文件与配置文件的真实路径绑定，跨项目、浏览器及安装版本共用，隔离配置文件分别保存。读取错误阻止初始化，处理状态写入失败不报告永久关闭。业务草稿取消不恢复提示，清空配置与升级不重置状态。

缺默认值的 `launch` 保存 `configuration_required` 阶段、输入指纹、已解析的正文边界与上下文标记，返回推荐组合、准确来源及可选动作。原请求尚未提交：明确选择推荐值后可用采用标记接续；通过配置页修复后使用原命令接续。新增预设不会重新解释等待中的正文；快捷采用绑定已展示的组合，升级改变推荐值不影响已确认的选择。保存检查原修订号、只填当前 Agent，接续使用锁内回读确认的值；并发保存不会偷换本次组合或回执修订号。输入/目录/配置对象/显式来源身份改变时拒绝同 ID 接续。`resume` 用于已准备或已提交的原操作，不代替缺项选择。恢复记录中已有提交结果时，采用标记不会再次保存或发起新启动。

若推荐值已保存但后续工作区预检失败，磁盘配置可以已生效，原请求记录仍处于 `configuration_required`。分别报告保存和启动结果；恢复环境后先回读配置，再用原调用且不加采用标记接续，不能把旧缺项回执解释为保存失败。

Windows 原生 Codex 的默认沙箱使用独立身份，可能无法读取其他用户保存的私有配置或运行程序。遇到权限错误先报告具体路径和失败层，按宿主正常授权与运行时恢复规则处理，不扩大配置文件权限或关闭沙箱来掩盖问题。只有已按锁文件准备并验证过的环境，才可用 `uv run --no-sync --offline --frozen` 排除无关的同步和缓存访问。
