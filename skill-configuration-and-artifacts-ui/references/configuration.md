# 配置管理

涉及配置能力时读取本文件。配置中心指承担配置管理的界面，可以是统一工作台中的区域、已有界面或独立页面；采用哪种页面和模板由业务方案决定。配置方式、数据与保存语义适用于所有涉及配置的实现，模板交互见文末。

配置管理应覆盖补齐必要设置与主动查看/修改设置的实际需求。UI 启动独立于业务凭证，缺项不能阻止页面启动。已填的持久设置仍可查看和再次修改；只读与敏感值规则照常生效。

页面绑定明确 Skill/Plugin 及本次项目。先展示当前生效配置及逐项来源，再选择本次保存范围与具体文件。配置层的来源说明和保存目标选择是配置管理能力，不等于 Secret Book 等凭证提供方选择。文件选择仅限真实加载器声明的目标，不提供任意磁盘路径浏览器或没有意义的单选服务。

## 配置方式与存量改造

配置中心由用户直接填写、查看和修改设置，保存到目标已确认的本机配置。Secret Book（`secret-book`）已退出本 Skill 的配置方案：新建不引入，改造不作为独立、可选、备用或兼容入口保留，也不委托它取值、保存或修复配置。这一边界覆盖方案、界面和非 UI 流程，不能仅隐藏页面入口。

改造时查清目标中的来源选择、命令分支、缺项/修复引导、调用方与使用说明，将相关入口改接配置中心；无其他用途的 Secret Book 专属代码随之移除。只评估时列出这些必要调整，不执行修改。涉及本次授权范围外的调用方时报告依赖与未完成范围，不以另留旧入口作为完成方案。

已有本机配置继续通过真实加载器读取，保留其分层优先级、保存范围及有效值；曾由 Secret Book 写入的值也是已有配置。退出该方式不授权读取、迁移或删除用户的 Secret Book 数据、凭证及其他项目配置。

## 字段与语义

- 全部配置覆盖目标正式支持的全部持久用户设置和高级项；Plugin 共享项集中展示，各 Skill 专用项分组并说明影响。宿主设置仍归宿主管理。
- 每次任务的临时参数留在原任务入口，用户明确要求才纳入 UI。若进程环境参与实际加载，应作为只读来源说明其覆盖效果。顺序列表、依赖、只读和生效时机保留原含义。
- 区分当前生效值及来源、各文件自己的显式值、本次编辑目标。切换编辑文件不会改变当前来源标签；保存成功也可能仍被更高层遮蔽。读取顺序不决定写回位置。
- 按真实加载器逐项解释继承，不把部分项目配置描述为整份全局配置失效。例如：**“当前项目仅覆盖 API Key，其余配置项继承全局配置。”** 若协议是逐字段首个非空值，缺项与空值继续回退，`0` 和 `false` 保持有效；全部来源缺失后才按字段定义使用默认值或报缺失。其他协议如实表达，UI 不自行变更语义。
- 同一作用域也可能有多个文件；完整明细包含它们的实际顺序、未设置/空值/被覆盖/未启用/错误状态及共享影响。全局启用条件、独立 Skill 与 Plugin 的差异从目标加载器取得，不把示例的十层顺序固化为通用规则。参与加载的文件不可读时按原协议报告错误，不伪装成缺项或继承成功。
- 身份、工作区、资源等绑定记录按目标协议整组读取与校验，不跨文件拼接。以一个配置项编辑完整记录，缺项明确报错。
- 保存目标由已确认方案和业务写入规则确定。单一目标不渲染选择器；多目标可在项目/全局范围内进一步选择具体文件，展示准确路径与共享影响。新增项目密钥遵守目标的私有本地文件与 Git 忽略要求，不因该文件优先级低就改写高层。

## 敏感值与保存

已保存密钥默认中间脱敏；眼睛按钮按用户动作读取并显示原始值，再点隐藏。替换与清除是独立编辑动作，刷新重置为脱敏。掩码不是表单真实值，不能提交或写回。短密钥避免暴露全值。日志、通用状态、任务回执、异常与 Agent 回复不包含原值。

一次“保存”提交所选文件的变更，保存前在页面显示范围、位置和变更摘要；编辑不自动写入，不加第二次确认。预览通过适配器调用与正式读取一致的解析逻辑，说明移除或设为空值后实际使用哪个来源、是否仍缺失/错误，以及低层保存后是否仍被覆盖；前端不以 `default` 代替继承计算。敏感预览和每层明细也脱敏。

定制界面的保存交互按已确认方案实现；修改范围、保存动作和反馈清楚可达。草稿按目标文件隔离，切换字段、作用域、文件、筛选与关闭编辑面板均保留草稿。只保存当前文件，其他文件草稿不丢失；预览与保存失败保留输入，错误位置可见。重载后提示核对新生效结果，不自动覆盖外部修改。

服务端复核类型、枚举、依赖、必需项和只读权限。验证失败不部分保存。写入前检测读取以来的文件/语义变化；冲突保留页面草稿，提示重新载入核对。多文件目标必须使用目标自己的事务/回滚机制；单机锁只协调参与同一协议的写入方。

## 保存后接续

保存回执仅包含任务标识、必要的输入/项目绑定、配置修订号、校验类型及结果。仍在等待的 Agent 核对任务和授权有效、配置已满足后继续原任务；本次保存并不授权新任务或结果不明请求重发。会话结束时显示可复制的继续请求。配置保存不代替 Agent 重发业务调用。连通性/鉴权校验需由目标实现明确标记，普通格式校验不能宣称 API 可用。

## 配置模板交互

选用本 Skill 的配置模板时，采用以下交互；完全定制或已有界面不必复制此布局。

主界面是“当前生效配置”，用稳定的“项目覆盖 / 继承全局 / 临时覆盖 / 字段默认 / 缺失或错误”标签解释各项。按全部来源、项目覆盖、继承全局筛选；概览用实际计数描述混合来源，不将编辑目标当作生效来源。

“必要配置 / 全部配置”与来源筛选分别控制字段范围。必要配置显示当前依赖条件生效的全部必填字段，包括已填项和高级必填项，保存后仍能二次编辑。业务缺项时进入必要配置，主动管理时进入全部配置；两者共用定义、预览、校验与保存逻辑。

点击字段打开侧边编辑抽屉，窄屏使用全屏。先选择“仅此项目 / 个人全局”，显示准确保存文件及影响；“更改文件”展开具体选择，“来源与优先级”展示完整链。单文件或只读字段按实际能力简化，不伪造不存在的全局层。

抽屉底部保存栏持续可见，显示当前文件和全部草稿计数、变更摘要入口与“保存此文件”。摘要默认收起，展开后显示本文件所有修改的生效结果及校验说明，长内容内滚动；成功与失败反馈在收起时仍可见。关闭抽屉保留草稿，可从主界面的草稿入口返回。桌面和窄屏均验证最后控件无遮挡、保存可达、焦点留在抽屉及 Escape 关闭。
