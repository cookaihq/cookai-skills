# 配置管理

涉及配置能力时读取本文件。配置中心指承担配置管理的界面，可以是统一工作台中的区域、已有界面或独立页面；采用哪种页面和模板由业务方案决定。配置方式、数据与保存语义适用于所有涉及配置的实现，模板交互见文末。

配置管理应覆盖补齐必要设置与主动查看/修改设置的实际需求。UI 启动独立于业务凭证，缺项不能阻止页面启动。已填的持久设置仍可查看和再次修改；只读与敏感值规则照常生效。

页面由本地服务提供，Agent 的启动入口绑定明确 Skill/Plugin 及本次项目，不让静态 HTML 猜测当前项目。优先展示本次目的相关的字段与当前缺失的必要配置；来源和文件细节按需展开。文件选择仅限真实加载器声明的目标，不提供任意磁盘路径浏览器或没有意义的单选服务。

## 已确认的配置交互规则

字段与允许范围由业务决定；以下保存语义适用于配置表单及音色库、资源选择器等扩展入口。选用共用模板时采用逐项范围块，不恢复整张表统一保存范围。

1. **查看、草稿目标、生效来源分开。** 展开来源详情只读取。选择项目／全局或明确文件将该项暂存到新目标，不写盘、不改变已生效勾；取消切换保持之前的值、目标和清理意图。
2. **差异必须显式选择。** 目标为空可转存当前有效值，目标相同可免写目标；目标已有不同值时，在弹框中明确采用目标或本次输入，不静默覆盖。敏感值比较在服务端完成，不把掩码当输入。
3. **确认绑定相关内容。** 差异和清理确认绑定本项输入、目标及实际依赖的来源修订；相关内容改变后失效，无关字段变化不使整页冲突。取消不修改已有草稿。
4. **清理遵循真实优先级。** 高到低切换的确认弹框写明“保存后将清除……”，逐项列出设置名称、真实 key、全部高层文件完整路径及共享影响。确认只暂存意图；目标写入和全部清理在底部保存时作为同一原子组。低到高保留低层内容，不提供额外“保存并使用”。
5. **以原加载器证明结果。** 进程环境只读，不能完成的切换只使相关组失败；普通保存成功仍被覆盖时如实报告。区分已保存、实际生效和业务鉴权；保存不以网络或付费请求为条件。
6. **按类型区分空值。** dotenv 空白可回退，false、0、合法空集合仍可为有效值。继承、明确关闭、清空收藏和删除分别处理。已有输入被清空不搬移目标，空密码占位不表示删除。
7. **独立项允许部分成功。** 只消费已确认成功的草稿，失败、冲突及待确认项的输入和目标保留，并逐项报告。共享文件不等于必须整组提交；保存保留未知字段和其他工具设置。
8. **校验按真实依赖分组。** 只验证提交项与实际依赖，不借用未提交草稿。身份绑定、目录选择与受影响的业务项、目标写入和高层清理保持原子；无关模型、偏好损坏或业务缺项不阻止其他有效项。无法安全解释目标文件时拒绝相关更新，保留原件及诊断。
9. **文件和偏好如实呈现。** 同名文件可区分，完整路径放在文件名下。仅支持独立 settings.json 的偏好只展示真实范围；不制造项目／全局对称操作。查看与预览不写配置、忽略规则或回执。
10. **统一保存并核对未知结果。** 只有底部“保存修改”持久化。选择器、清除确认和范围选择都只暂存。响应丢失先查询原操作并回读，不自动重复写入／清理；确定失败可纠正后重试，证据不足时保留待确认状态。到期保留可见输入并禁用变更。

扩展选择器与主表使用同一份草稿及同一保存路径。打开时读取现有草稿，筛选、关闭再打开不丢失；只改收藏时不重写默认音色。默认范围全局只是本次保存偏好；仅提交实际修改或用户明确转存的字段。已有选择器的视觉与布局可保留，将差异选择、外部变化、未知结果和到期状态接到它已有的反馈区域。后台缓存加载、重新下载与分页不创建配置草稿。

保存成功后留在页面，提供“配置已保存，请继续。”复制消息供用户发送；不自动执行业务。

## 配置方式与存量改造

配置中心由用户直接填写、查看和修改设置，保存到目标已确认的本机配置。Secret Book（`secret-book`）已退出本 Skill 的配置方案：新建不引入，改造不作为独立、可选、备用或兼容入口保留，也不委托它取值、保存或修复配置。这一边界覆盖方案、界面和非 UI 流程，不能仅隐藏页面入口。

改造时查清目标中的来源选择、命令分支、缺项/修复引导、调用方与使用说明，将相关入口改接配置中心；无其他用途的 Secret Book 专属代码随之移除。只评估时列出这些必要调整，不执行修改。涉及本次授权范围外的调用方时报告依赖与未完成范围，不以另留旧入口作为完成方案。

已有本机配置继续通过真实加载器读取，保留其分层优先级、保存范围及有效值；曾由 Secret Book 写入的值也是已有配置。退出该方式不授权读取、迁移或删除用户的 Secret Book 数据、凭证及其他项目配置。

## 字段与语义

### 完整配置目录

开发配置管理能力时，将自定义完整全局／当前项目配置目录作为通用能力接入；目标不具备某一范围时，只提供真实支持的范围。具体默认目录、持久 Key、允许的文件与旧来源退出政策由业务适配器声明，不将某个 Plugin 的选择推广到核心。

目录设置本身是普通配置，保存在默认位置的既有文件中，不新增独立定位文件。加载分两步：先从固定默认位置和目标已支持的只读环境来源解析目录，再从选定根内读取业务配置。自定义文件中的目录 Key 不递归跳转。文件不存在与不可读分别处理，环境优先和按次关闭全局沿用业务协议。

完整根包含该范围的全部配置文件、Skill 子目录和独立 `settings.json`；目录切换不改变项目工作目录、身份绑定或任务产物位置。只读取不创建目录、不搬迁、不复制或删除旧配置。是否退出旧业务根及独立 Skill 回退由目标明确决定，退出文件不能再补齐或报不可读错误。

目录与业务共享草稿和底部保存。保存先投影目录设置，再用原加载器解析新根，将同次明确修改的业务项写到新根对应文件；未改字段不复制。目录字段始终写固定默认锚点，不跟着自己跳转。只改目录时不创建业务文件；恢复默认移除锚点中的该项，保留旧根和新根内容，并按实际环境覆盖计算结果。保存前显示实际目标路径，保存后回读真实来源；有效源不等于目录设置的保存位置。

修订号涵盖固定锚点、当前根及候选新根的参与文件和环境输入；保存内再次计算候选，提交前复核新根来源与目标，目录及其真实影响项参加同一原事务和恢复，独立组可分别成功。相关冲突、不可写、Git 跟踪、不支持的路径重定向或回读不一致时停止该组并保留草稿；不能先保存锚点再另存业务项。

共用模板在顶部当前项目路径旁提供低调的“配置文件位置”文字入口，初始收起。展开后在正文标题上方显示目标声明的全局／项目目录字段、默认位置与固定保存文件，并提供恢复默认；收起、预览与重新展开保留草稿。具体协议见 [代码接入](integration.md#目录字段与组合投影)。

- 开发者决定哪些持久用户设置和高级项适合通过页面查看、修改；其他设置继续可由 Agent 协助配置。已纳入页面的字段可从同一表单展开；Plugin 共享项集中展示，各 Skill 专用项分组并说明影响。宿主设置仍归宿主管理。
- 在字段的来源详情中显示真实配置 Key 或 JSON 路径，长名称允许折行。由适配器声明真实字段与 UI 内部 ID 的映射，不能从按钮 ID、中文标题或密钥值猜测。编辑和刷新后仍可查看准确标识；敏感值的脱敏规则不变。
- 每次任务的临时参数留在原任务入口，用户明确要求才纳入 UI。若进程环境参与实际加载，应作为只读来源说明其覆盖效果。顺序列表、依赖、只读和生效时机保留原含义。
- 区分当前生效值及来源、各文件自己的显式值、本次编辑目标。查看文件不会改变草稿目标或当前来源标签；保存成功也可能仍被更高层遮蔽。读取顺序不决定写回位置。
- 按真实加载器逐项解释继承，不把部分项目配置描述为整份全局配置失效。例如：**“当前项目仅覆盖 API Key，其余配置项继承全局配置。”** 若协议是逐字段首个非空值，缺项与空值继续回退，`0` 和 `false` 保持有效；全部来源缺失后才按字段定义使用默认值或报缺失。其他协议如实表达，UI 不自行变更语义。
- 同一作用域也可能有多个文件；完整明细包含它们的实际顺序、未设置/空值/被覆盖/未启用/错误状态及共享影响。全局启用条件、独立 Skill 与 Plugin 的差异从目标加载器取得，不把示例的层数或顺序固化为通用规则。参与加载的文件不可读时按原协议报告错误，不伪装成缺项或继承成功。
- 目标支持 `.env.local.<plugin-name>` / `.env.<plugin-name>` 时，将两者作为独立项目来源，按业务协议排序并说明同 Plugin 多 Skill 共用的影响。默认保存目标、可新增 Secret 的本地文件和普通文件的已有值修复分别声明，来源、预览、目标白名单与保存后回读保持一致；不因文件名相似合并层或推断权限。
- 目标已确认退出某些来源时，只移除那些准确路径的读取、来源展示和保存入口，测试其中有值或不可读也不会参与。Skill 后缀文件、Skill 子目录与普通 Skill 全局回退是不同来源，保留范围按该目标决定；某个 Plugin 的退出政策不变成通用核心规则。
- 身份、工作区、资源等绑定记录按目标协议整组读取与校验，不跨文件拼接。以一个配置项编辑完整记录，缺项明确报错。
- 保存目标由已确认方案和业务写入规则确定。单一目标显示真实范围与详情；多目标可在项目/全局范围内进一步查看和明确选用具体文件，展示准确路径与共享影响。新增项目密钥遵守目标的私有本地文件与 Git 忽略要求，不因该文件优先级低就改写高层。

## 敏感值与保存

已保存密钥默认中间脱敏；眼睛按钮按用户动作读取并显示原始值，再点隐藏。替换与清除是独立编辑动作，刷新重置为脱敏。掩码不是表单真实值，不能提交或写回。短密钥避免暴露全值。日志、通用状态、任务回执、异常与 Agent 回复不包含原值。

底部“保存修改”统一提交普通草稿及已确认切换意图；单项和选择器动作只暂存，保存前显示范围和修改计数，准确文件及来源按需展开；编辑不自动写入，不加第二次确认。预览通过适配器调用与正式读取一致的解析逻辑，说明移除或设为空值后实际使用哪个来源、是否仍缺失/错误，以及低层保存后是否仍被覆盖；前端不以 `default` 代替继承计算。敏感预览和每层明细也脱敏。

定制界面的保存交互按已确认方案实现；修改范围、保存动作和反馈清楚可达。草稿按目标文件隔离，切换字段、作用域、文件、筛选与关闭编辑面板均保留草稿。部分成功只消费成功字段，失败草稿保留并重新核对；预览与保存失败保留输入，错误位置可见。重载后提示核对新生效结果，不自动覆盖外部修改。

服务端复核类型、枚举、依赖、关联完整性和只读权限，区分保存阻塞错误与业务必要缺项。独立有效项允许保存成功；原子组失败须恢复或报告待确认。写入前核对相关字段、依赖和清理目标，无关并发变化合并保留；冲突不自动接受新基线后覆盖。多文件目标必须使用目标自己的事务/回滚机制；单机锁只协调参与同一协议的写入方。

保存已授权的配置时，自动准备必要的 Git 忽略保护：配置文件、实际临时文件、锁文件，以及业务需要的私有恢复目录。只追加对应位置的精确规则，保留用户原有内容；转义路径特殊字符，在实际目录处理嵌套否定，再以 Git 复核未跟踪且已忽略。重复保存不重复增长规则。已跟踪的配置或恢复内容仍拒绝写入，不改 Git 索引。检查失败保留草稿，说明 Git、目录权限或忽略规则的具体阻塞，修复后可重试；不自动迁移配置或改写其他来源。读取、来源展示和保存预览不准备忽略规则或写配置。确定不在 Git 工作树中的目标不调用 Git；仍验证实际路径和文件保护。运行与恢复材料使用用户可写本地位置，全局保存不依赖当前项目可写。目录始终沿用 OS／父目录默认权限；私密文件单独保护，并验证实际使用者可读。稳定、明确的目录链接按规范化真实目标协调，叶子文件链接、未知重定向和越界目标局部失败。

## 保存后接续

保存回执仅包含任务标识、必要的输入/项目绑定、配置修订号、校验类型及结果。保存后留在页面，按钮下提示用户回到 Agent 对话窗口发送“配置已保存，请继续。”收到消息后，Agent 核对原任务、项目、授权及当前配置，满足条件才继续；仍缺必要项则指出缺项。本次保存不授权新任务或结果不明请求重发。连通性/鉴权校验由目标明确标记，普通格式校验不能宣称 API 可用。

## 配置模板交互

选用本 Skill 的配置模板时，采用以下交互；完全定制或已有界面不必复制此布局。

主界面是直接编辑的表单。Agent 通过本次链接的字段选择或适配器展示信息确定焦点；页面始终补入必要缺项。其他配置按稳定分组在“其他设置”中展开，不使用模式切换、来源筛选或侧边抽屉。

每项输入下显示实际支持的范围块，项目在左、全局在右；默认不列文件名，真实生效位置用小勾表示。无来源的空值以不同样式标注默认保存位置。点击范围块选择草稿目标并原位展开详情；需要差异或清理确认时先显示弹框。当前来源旁不另设“保存本项”。同名文件须能区分，完整路径放在所选文件名下。

删除使用锚定在删除按钮旁的确认气泡，展示本项删除、共享影响及真实回退结果；确认后只暂存这个文件中这一项的删除；如替代本项未保存输入须明确提示。底部保存才提交。取消、Escape、点外部可关闭；保存失败保留输入。删除不再叠加下方待删区或第二个保存按钮。清空内容与删除记录仍有不同语义。

表单内容区最大 800px，底部保存条固定，与内容同宽；按真实栏高给文档预留空间，不遮挡末尾控件。保存结果在按钮下，反馈过长时可滚动。桌面、窄屏、键盘、预览后焦点及选区均须验证。默认值、来源与业务规则不能只靠样式表达。
