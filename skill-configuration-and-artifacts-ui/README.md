# Skill 配置与产物 UI

给 Skill / Plugin 开发者使用：评估、接入或改造配置与产物界面。Agent 先调查业务流程和已有界面，再分别与你确认需要哪些可视化能力、采用一套统一界面还是多个页面、是否适合本 Skill 的模板。可以无需 UI、保留或改造已有界面、局部复用模板，也可以完全定制。

选用配置模板时，配置中心既能补齐 API Key 等必要信息，也能查看和修改全部持久设置。“必要配置”保留已填好的必填项，随时可修改；保存栏固定在页面底部，默认收起显示修改数量，点击展开可查看变更摘要与校验说明。展开或收起保留草稿和保存按钮位置，保存结果始终可见。产物模板使用集合与专注预览，可展示文档、图片、音视频、表格和业务回执。定制界面按业务安排这些交互，不必采用模板布局。

涉及配置时，通过承担配置管理的界面直接填写和修改，不再采用 Secret Book；该界面可以是统一工作台的一部分。改造已有目标时，Agent 会把相关配置入口和缺项、修复引导接到这里，不另留独立或备用入口；已有本机配置继续有效，用户凭证和 Secret Book 中的数据不会因此迁移或删除。

只有同时选用两个共用模板时，两个页面才分别启动、计时和结束；只选一个模板只启动对应页面。产物模板可为本次服务勾选常驻，并显示资源占用提示。定制统一界面按确认方案管理访问期限，配置访问仍会到期。采用共用代码时由业务 Skill / Plugin 携带固定版本；完全定制可以不引入它，最终使用者均无需安装这个开发 Skill。

## 安装

支持 Claude Code、Codex 和 WorkBuddy。把下面这段话发给你使用的 Agent：

```text
请优先从 https://github.com/cookaihq/cookai-skills 安装其中的
skill-configuration-and-artifacts-ui，网络故障时尝试 https://cnb.cool/zhidateam/tannt/tannt-skills，
使用当前 Agent 支持的用户级 Skill 入口。
安装完整目录，保留 references、assets、examples、scripts 和锁文件，
然后在新会话中验证发现和调用。
```

Claude Code 使用用户主目录 `.claude/skills/skill-configuration-and-artifacts-ui/`；Codex 使用 `.agents/skills/skill-configuration-and-artifacts-ui/`，展示名为“Skill 配置与产物 UI”。WorkBuddy 使用其原生本地 Skill 导入/安装入口，导入同一完整目录，不依赖 Codex 展示配置。WorkBuddy 的安装器能力由 Agent 在当前客户端核实，不能把另一个宿主的链接可用视为导入成功。

本 Skill 无需 API Key 或业务账户。Agent 运行示例与接入工具时使用 uv 0.8+ 和随包固定的 Python 3.13；缺少 uv 时会说明当前设备的准备方式。

## 第一次使用

向 Codex 发送（其他 Agent 可直接点名同名 Skill）：

```text
使用 $skill-configuration-and-artifacts-ui，检查当前项目里的 <目标 Skill 或 Plugin>。
先判断是否需要 UI，再根据业务流程建议页面组织和实现方式，说明是否适合采用你的模板。
需要界面时先给展示方案和可运行预览，经我确认后再接入。
```

把 `<目标 Skill 或 Plugin>` 替换为实际名称或目录。你会得到基于源码的必要性、页面组织和模板选择建议，以及实际需要的展示方案、预览和确认后的接入。无需 UI 时直接交付评估结论；即使同时涉及设置和结果，也可以在一套界面中完成。

## 改造已有 Skill

```text
用 skill-configuration-and-artifacts-ui 改造这个已有 Skill。
先调查现有界面和用户配置；我想先看看新界面，再决定保留、补充还是替换。
如果缺少运行记录，请提出采集、存储、保留和历史覆盖方案让我确认。
```

再次接入会核对已有界面与定制内容；采用共用代码时同时核对其版本，发生冲突先给出差异，不覆盖用户配置或业务适配。可让 Agent 只评估或只做预览。实际验收使用哪些 Agent 由你选择，已有决定继续沿用。

讨论或预览反馈同时涉及多项相互影响的改动、又有关键问题未明确时，Agent 会结合具体缺口，建议你是否使用 `mattpocock-skills:grill-with-docs` 梳理需求。它会提供当前 Agent 中可用的显式调用入口；尚未安装或无法核实入口时会说明情况，也可继续普通澄清。你可以拒绝，同一问题不会反复推荐；选择梳理后会保留已确认决定，结束时接回原来的设计、预览或实施阶段。简单调整或已说明清楚的复杂需求直接继续。

## 查看示例与跨设备访问

```text
启动这个 Skill 自带的配置中心和产物集合合成示例，给我两个本机链接。
```

示例仅写入指定演示项目，不调用真实 API；请只填合成密钥。

交付链接时，Agent 会说明访问期限，并提供三条已填好实际页面名称、业务 Skill 名称和项目位置的重开请求：分别用于当前会话、当前项目的新会话、其他项目的新会话。按所在位置复制对应请求即可。新会话会从目标项目说明找到入口，先核对服务再给出可用链接；项目或临时预览数据已删除时会说明缺项，不能恢复的内容不会被承诺可重开。

**📱 手机或其他设备访问需要 FRP 或 Tailscale。** 已配置时可发送：“用 FRP 开放这个产物预览，给我手机可访问的链接。”没有安装配置时，需先请 Agent 安装配置；仅安装完成不代表页面已经可访问。

## 遇到问题

- “页面打不开，请核对这次项目和页面的服务状态、访问期限及完整链接。”
- “保存提示配置已改变，请保留我的修改，检查实际文件差异和生效范围。”
- “已有产物没显示，请检查项目归属与记录覆盖，不要扫描其他项目或补造历史。”
- “升级提示共用代码有本地修改，请比较差异并提出保留定制的方案。”

保存成功只表示所显示的配置校验已完成，不代表外部 API 或业务任务成功。Agent 会核对原任务再继续；会话结束时页面可提供继续请求。停止 UI 保留配置与成果。
