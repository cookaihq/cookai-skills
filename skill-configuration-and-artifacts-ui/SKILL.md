# Skill 配置与产物 UI

面向开发者的新建接入与存量改造工具。处理用户指定的 Skill / Plugin，按业务需要选择界面组织与实现；采用本 Skill 的模板时，所需运行代码随目标产物分发。本文路径相对于本 Skill 的实际安装目录；目标路径相对于用户明确的目标项目。

## 0. 检查更新

每次调用先执行 `scripts/check_update.ps1`（Windows 原生 PowerShell）或 `scripts/check_update.sh`（macOS / Bash）。退出码 0 继续，不复述例行输出；10 原样展示更新报告并询问是否拉取，同意才用同一脚本的 `--pull`（PowerShell 为 `-Pull`）。用户未回应、检查或更新失败均按当前版本继续。复制安装按 [更新协议](references/update.md) 查询固定 tag/commit。用户要求关闭时只修改用户主目录 `.config/skill-configuration-and-artifacts-ui/.env` 的 `AUTO_UPDATE_CHECK=0`。

## 1. 调查并决定适用性

读取 [调查与改造](references/assessment.md)；涉及配置时，在形成方案前同时读取 [配置规则](references/configuration.md)，按其中的配置方式边界调查存量入口。查目标业务流程、源码、已有 UI、配置加载与保存、输出与任务记录、发布包和宿主入口。分别判断需要哪些界面能力、如何组织页面、是否采用本 Skill 的模板，给出证据与建议，沿用用户仍适用的决定。可以无需 UI、保留或改造已有界面、采用统一工作台或多个页面；实现可局部复用模板或完全定制。此开发 Skill 本身不需要业务配置或产物服务，不递归给自己接入 UI。

初次需求、后续追加调整或预览反馈出现复杂且影响方案的关键缺口时，按 [复杂需求澄清](references/assessment.md#复杂需求澄清) 主动推荐 `mattpocock-skills:grill-with-docs`，沿用用户选择后接回当前阶段。

完成条件：目标和项目明确，每项涉及的配置/产物可对应实际读写或记录入口；配置调查包含同一作用域的全部文件、真实优先级、逐项生效来源及独立保存目标。必要性、页面组织、模板选择及存量 UI/记录处置分别明确。仅评估请求到此交付方案，不擅自改造；确定无需 UI 时直接交付结论，省略页面预览、接入和链接交付。

## 2. 确认展示与预览

涉及产物时读取 [产物规则](references/artifacts.md)；启动任意页面前读取 [生命周期与访问](references/access-and-lifetime.md)。按调查结果仅列出实际涉及的展示内容、页面和待选项。新界面或明显变化先做可运行的合成数据预览，用户确认后真实接入。已确认且仍适用的界面无需再选一次。

## 3. 接入或改造

按已选实现接入：保留/改造已有界面或完全定制时使用目标自身入口，无需引入本 Skill 的运行代码；选用共用核心时才读取 [代码接入](references/integration.md)，用 `scripts/vendor.py` 检查差异并带入固定版本核心，业务适配与定制文件放在核心之外，Plugin 共用一份核心。局部复用仅接入实际采用的部分，并遵守对应契约。所有实现均使用目标已有的配置和数据协议，不能用示例 JSON 文件替换原加载器。

改造保留仍受支持的原命令与业务行为；已退出的配置方式按 [配置规则](references/configuration.md#配置方式与存量改造) 清理入口与调用方，不能因通用保留要求恢复。其他语义变化先提出具体方案，已有明确决定直接落实。共用包升级先核对版本、校验值和本地改动；冲突解决前不覆盖。使用者不依赖安装本开发 Skill。

## 4. 验收与交付

读取 [验收](references/acceptance.md)，沿用用户已选的实际验收 Agent；没有决定才询问，不按当前执行 Agent 推定。按选定能力、页面与实现分支完成受影响的原业务入口、UI、发布副本与所选宿主的实际验证，报告已测范围及缺口。

交付 UI 链接时按 [访问规则](references/access-and-lifetime.md#交付链接) 说明期限，填好三种会话下的重开请求，并给出醒目的 **📱 FRP / Tailscale** 跨设备提示。先验证目标项目中的重开入口可定位。涉及配置保存时，保存成功只代表配置保存及所声明校验通过；由仍在等待的 Agent 核对任务关联后接续授权任务，会话结束则提供继续请求。规则正文、代码与引用检查不能替代业务或宿主实测。
