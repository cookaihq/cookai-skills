# video-to-markdown

把一个视频整理成保留原始内容的 Markdown 文档：结合语音、带时间的截图、必要的短 GIF 和覆盖复核，适合课程、演示和操作说明。可以单独指定看图模型，支持静音视频，也可以明确跳过无关画面。处理本地视频或能直接下载的链接，不负责下载视频网站页面，也不自动发布文档。

## 安装与准备

把下面这段话复制给正在使用的 Claude Code、Codex 或 WorkBuddy：

> 请从 https://github.com/cookaihq/cookai-skills 安装 video-to-markdown，保留已有配置，检查当前宿主能否发现和调用它，并告诉我实际安装的版本。

Agent 会检查 uv、ffmpeg、ffprobe。Claude Code 的独立 Skill 入口是 `/video-to-markdown`，Codex 是 `$video-to-markdown`；也可以说明“用 video-to-markdown 整理这个视频”。WorkBuddy 应从本机实际支持的本地 Skill 入口安装并点名调用；其本地安装、Plugin 加载与开放平台上架是不同入口，不需要为了使用本 Skill 上架。

三宿主都是兼容目标，本轮必需实际验收宿主为 Codex。原生模型列表、指定子 Agent 模型和实际执行模型核验，取决于当前宿主暴露的能力；无法获取时会说明限制，不宣称 WorkBuddy 一定支持或一定不支持。4.1.0 在 Windows 原生通过 150 项脚本测试和类型检查，当前 Codex 会话通过正式源码入口完成固定设置播报、恢复后保留原方式、实际看图、截图复检、文档交付与完成后恢复，并检查跳过画面不播报识图。未受影响的配置页、采样及 GIF 行为沿用 4.0.0 已记录的验收范围。macOS/Linux/WSL、Claude Code、WorkBuddy、其他模型的原生派发和真实外部模型/转写服务尚未完成本轮实机验收。

## 看图方式与配置页

没有固定设置的新任务，会在同一轮列出四种方式及能取得的模型，让你直接选择：

| 方式 | 说明 |
| --- | --- |
| 主 Agent 看图 | 当前会话查看图片，继续写正文。 |
| 宿主子 Agent | 从当前会话实际支持的模型中选择，专门负责看图。宿主需支持指定模型和图片输入。 |
| 独立 Agent | 提供 Base URL、Key、模型和运行器；当前接入 Codex CLI 与 Responses 兼容的远程服务。 |
| 直接调用 API | 提供 Base URL、Key 和图片模型；当前接入 Chat Completions 兼容接口。 |

只有看图、补图和截图复核使用所选路径，主 Agent 的写作和语音转写不跟着换模型。模型目录、图片能力和账号可用性分别展示；已知禁用或不支持图片的模型不能选，无法核验实际模型时会先说明，由你决定是否接受。服务返回了另一模型会停止接收结果，不静默换模型。

每次开始或恢复任务，以及你要求切换看图方式后，Agent 都会在首次识图前主动说明采用的方式、计划模型、执行宿主或服务和配置来源；已有固定设置也会播报。实际模型尚未核验、主会话没有提供真实模型 ID 时会明确说明。同一次执行中不逐张或逐批重复相同信息；明确跳过画面的任务只说明跳过。

可以对 Agent 说：

> 请打开 video-to-markdown 的配置页，在一个页面展示四种看图方式、当前可取得的模型，以及项目/个人全局保存范围。先展示实际生效来源，我点击保存后再写入；保留其他配置。

页面默认折叠语音、输出和来源等低频设置，密钥默认隐藏。可以固定一种方式，也可以打开“每次新任务询问”。仅本次选择不会自动保存成长期默认；项目设置优先于显式启用的个人全局设置，已经开始的任务沿用原选择。配置预览、保存和回读不调用模型，保存成功也不代表服务鉴权或模型能力已验证。

页面仅在本机运行，空闲 60 分钟到期，操作会续期。过期或关闭后，对 Agent 说：“重新打开 video-to-markdown 在这个项目的配置页，先检查服务归属和状态，给我有效链接。”从其他项目重开时说明目标项目的完整路径。**📱 FRP / Tailscale：手机或其他电脑访问需要另行配置并验证，本机链接不能直接跨设备使用。**

## 转写方式与配置

有现成 SRT、VTT 或带起止时间的文字稿时直接使用，不上传音频。没有字幕时，两个选项并行提供：

| 选项 | 用途和准备 |
|---|---|
| AIhub Audio（内置默认） | 安装 AIhub Studio 中的 AIhub Audio Skill，由它管理 AIhub 凭证、模型和结果检查。 |
| 飞书妙记 | 安装官方 Lark CLI，选择飞书账号并由本人完成登录授权；需要云盘上传、妙记创建和导出权限及可用额度。 |

AIhub Audio 缺失、缺配置或明确失败时，会说明原因并尝试将**本次任务**转到飞书。首次飞书授权会暂停等待你完成。它不会因此修改以后任务的默认选项。AIhub 已提交但正在等待、下载失败、等待结果检查或提交结果不明时，继续保留原任务。

可以这样配置：

> 请将 video-to-markdown 的默认转写方式设为飞书妙记。帮我选择正确账号，展示应用和用户身份让我确认。默认保存到个人全局，并为任务显式启用读取；保留其他配置。

本 Skill 的默认保存位置是个人全局 `~/.config/video-to-markdown/.env`，只有任务显式启用个人配置（由 Agent 使用 `--use-local-key`）才读取。项目中已有设置时，Agent 会解释实际生效来源。飞书身份可以只绑定本次任务；长期保存身份也需要你确认位置。登录令牌仍由 Lark CLI 管理。

配置读取顺序：进程环境变量 → 你发起任务的工作文件夹中的 `.env.video-to-markdown` → `.env.local` → `.env` → 显式启用的个人全局文件。不搜索父文件夹，也不从安装目录或结果目录寻找配置。`VIDEO_TO_MARKDOWN_ASR_PROVIDER` 的值为 `aihub-audio` 或 `feishu-minutes`；当前请求的明确选择优先，已经开始的任务继续使用保存的选择。

| 运行环境 | 本 Skill 的个人全局位置 |
|---|---|
| macOS / Linux | 用户个人文件夹中的 `.config/video-to-markdown/.env` |
| Windows 原生 | 例如 `C:\Users\你的用户名\.config\video-to-markdown\.env`，按实际 Python 用户目录定位 |
| WSL | WSL 用户自己的 `~/.config/video-to-markdown/.env`，不自动读取 Windows 那一份 |

AIhub Audio 独立读取自己的配置。它依次读取环境变量、当前工作文件夹的 `.env.aihub-audio` / `.env.local` / `.env`，然后个人目录中的 `~/.config/aihub-studio/aihub-audio/.env.local`、同目录 `.env`、Plugin 根的 `.env.aihub-audio` / `.env.local` / `.env`，最后补齐 `~/.config/aihub-audio/.env`。Plugin 全局读取默认启用；Windows 使用其实际用户个人目录，WSL 与 Windows 分离。对话中说“这次禁用全局配置”可同时关闭两者的全局业务读取。

AIhub 转写凭证的缺项由 AIhub Audio 自己的配置流程处理；本 Skill 的页面只管理自己的看图连接与业务设置，不复制、迁移或保存 AIhub 转写密钥。

## 第一次使用

云端转写会上传提取后的音频，可能消耗 AIhub 或飞书额度。飞书会创建云盘文件和妙记；本 Skill 不自动删除这些云端对象。默认没有逐请求的付费确认门。可以先提供字幕，验证本地视频整理流程。

> 请用 video-to-markdown 整理我提供的这个视频和 SRT 字幕，保留原语言与内容顺序，结合截图和必要的 GIF，完成覆盖复核后把文档路径告诉我。

每批最多覆盖 5 分钟视频，首轮每 5 秒产生候选，另外检测整体和局部变化。完整一批约有 61 个周期及边界候选，变化检测可能继续增加。容量不够时拆成多次派发，保留图片；一个看图 Agent 按批连续处理多张图及补图，并非每张图启动一个 Agent。局部检测仍可能漏掉很短的事件，复核会结合字幕与未解决细节补采。

截图采用原分辨率 PNG。原图模糊时，默认在前后各 1 秒按 125 毫秒取邻帧，用 FFmpeg 评分，再由所选看图路径确认内容清晰且仍是同一页面/步骤；第二轮默认扩到前后各 2 秒。每个疑点默认最多自动补采或扩窗两轮，恢复不会重置。找不到可靠画面时，可交付标有具体时间和原因的“待复核草稿”，不会记为完整转换成功。

默认在调用时的项目根目录生成：

```text
data/video-to-markdown/20261108132559-原视频文件名.mp4/原视频文件名.mp4.md
```

时间编号精确到秒，原视频文件名保留扩展名。文件名是哈希、随机 ID 或纯时间等无法表达内容的字符串时，Agent 在完成内容复核后补充一个视频主题，例如：

```text
data/video-to-markdown/20261108132559-a8f93.mp4-表格筛选教程/a8f93.mp4-表格筛选教程.md
```

转换完成前不追加主题或多余连字符。有意义的原文件名不追加主题。Agent 会自动应用这一规则并返回最终路径。

本地视频还会在**原始视频所在目录**得到一份 Markdown 副本，旁边有同名 `.assets` 素材文件夹；一起移动这两项即可保留截图和 GIF。可以指定其他副本目录。下载链接没有本地原始目录，因此只有明确指定副本位置时才生成额外副本。遇到已有同名但内容不同的文件会停止复制，保留已有文件并请你选择其他位置。

可以说：“把任务保存到 D:\资料\视频整理，另外把 Markdown 副本放到 D:\笔记。”Agent 分别使用 `--output-parent` 和 `--copy-dir`；副本位置不改变完整任务的存储位置。设置 `VIDEO_TO_MARKDOWN_TASK_OUTPUT_DIR` 时，该基目录下仍追加 `data/video-to-markdown/`。

转写完成后还需要 Agent 查看画面、补采样、写正文并复核，只有任务 ID 或字幕不算整份文档完成。副本失败可继续同一任务完成复制，无需重新转写。

## 常用请求

- “这次优先使用飞书妙记，不修改以后默认。”只改变新任务的本次通道。
- “这次只能使用 AIhub Audio，不要向飞书上传。”禁止自动跨平台切换。
- “飞书额度用完后，这次切换并把以后默认设为 AIhub Audio。”Agent 会区分本次切换与默认保存是否实际生效。
- “继续这个任务文件夹。”恢复保存的输入、账号和任务。不要通过重新开始来重试结果不明的上传。
- “先暂停，我稍后登录。”保存任务；稍后继续原任务或选择当时提供的安全切换选项。
- “画面与内容无关，只根据语音/字幕生成文档。”直接跳过看图选择、抽帧、截图、GIF 和视觉复核。
- “这是没有音轨的操作演示，请按画面整理。”跳过转写，按可核验画面成文。
- “仅看图改用另一个模型，写作继续用当前 Agent。”列出当前可用方式和模型，明确受影响批次后重做相应观察。
- “最多调用模型 20 次。”可计数的 API 路径按上限执行；无法计数内部请求的 Agent 路径会说明无法强制该上限，不把一个 Agent 任务当作一次请求。

## 限制与排障

音频使用完整的第一条音轨，转换为单声道 MP3；记录音轨、时长、哈希及视频时间偏移，不自动截断或拆分收费任务。AIhub 本地上传上限为 20 MiB；飞书上限为 6 小时、6 GB，实际账号或模型可能更严格。无音轨时可以仅按画面整理；同时跳过画面且没有有效字幕/语音时，会说明缺少内容来源。

飞书导出的是句段时间，不能承诺每个字出现的准确时刻。AIhub 实际返回词时间时会保留；缺失、倒序或越界时间会阻止完整证据交付。显示到毫秒不代表识别准确到毫秒。

遇到问题可对 Agent 说：“检查这个任务的下一动作、配置来源和已有远端 ID，先说明可恢复到哪一步。”登录、权限、额度、网络和结果不明分别处理。结果下载失败应补下载原结果。AIhub 出现已知任务 ID 但依赖落盘失败时可以按该 ID 查询；把另行恢复的子任务接回原运行及结果检查的公共接口尚未核实，Agent 会报告这一限制，不能擅自重新转写。

远程看图会向所选服务发送候选图片及必要字幕背景；API 和独立 Agent 可消耗该服务额度，没有逐图或逐请求确认。网络结果不明时先查保存的响应，不盲目重发。Key 保留在原配置/私有连接文件，任务只保存引用；请保留恢复所需来源。

分享时只提供正文和引用素材，不分享 `.state/`：其中包含私有恢复记录、原始响应和临时链接。校验主要检查结构、引用与时间范围，语义仍须实际复核。4.0.0 校验静态截图的真实解码 PTS，覆盖长 GOP、非零起点和小数帧率；GIF 保留其独立时间与语义验证要求，不承诺所有视频格式都已实测。

## 从 3.x 升级

4.0.0 新建任务使用新的看图选择、派发和检查记录，替换旧观察录入入口。旧任务文件保持原样，不提供格式兼容、盘点或迁移，不自动重建任务或重新提交转写。新任务的配置设置与已发布的命名、副本规则继续有效。

## 从 2.x 升级

3.0.0 改用上述目录、命名和副本规则。已有任务和文件保持原样，但不提供旧任务格式的续跑或迁移；不要用新建任务重试结果不明的旧转写请求。

## 从 1.x 升级

2.0.0 删除了 Skill 自己的 AIhub HTTP 客户端和凭证别名，不自动搬动真实密钥。旧 `VIDEO_TO_MARKDOWN_ASR_MODEL` 必须由 Agent 核对意图后迁移到 AIhub Audio 的模型配置；不能悄悄改用默认型号。旧任务文件保留，但其旧状态格式不能由 v2 直接续跑，也不会被自动重新提交。升级前请保留需要查询的原任务材料。

## 更新

本 Skill 默认自动检查更新，更新本身需要你确认。Git 安装使用系统对应的随包检查脚本；复制安装按 `update.json` 的稳定版本及固定提交检查。WorkBuddy 不具备已核实的更新入口时会说明未完成并继续当前任务。

可以说：“检查 video-to-markdown 是否有新版本，先告诉我变化。”也可以说：“关闭它的自动检查更新。”这个开关只保存在个人全局文件中的 `AUTO_UPDATE_CHECK`，独立于业务配置的读取优先级；检查失败不会阻止处理视频。
