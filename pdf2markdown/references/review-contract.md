## Review Evidence

Open a review by running `resume --visual-capability available`. Preserve the returned `generation`, `action_id`, and `evidence_hash`. Read the evidence path returned as `artifacts.review_evidence`.

The evidence binds:

- `target`: the exact raw or corrected Markdown identity, parser profiles, GFM dialect, semantic hash, and validated local targets;
- `baseline`: the frozen source PDF, source inventory, and every page reference image;
- `markdown_blocks`: ordered block IDs and source ranges from the target parser;
- `markdown_block_boundaries`: parser-derived adjacent block evidence;
- `segment_boundary_policy`: ordering used to derive required adjacent review-segment pairs;
- `prior_rounds` and `coverage_mode`: cumulative progress for an incomplete review or fresh coverage after a correction;
- `structural_validation`: the Pandoc, lexical, safe-HTML, URL, formula, table, reference, and fence result.

Do not edit this file. Inspect every referenced page image and use the source inventory for non-visual evidence. Bind conclusions only to IDs present in this evidence.

## Review Record

Submit a strict JSON object with exactly these top-level fields. The following shows the key shape only: `segments` must be populated before submission, and the other arrays must follow the rules below.

```json
{
  "schema_version": 1,
  "status": "local_complete",
  "segments": [],
  "boundaries": [],
  "findings": [],
  "page_misc": [],
  "absence_basis": []
}
```

`segments` must be non-empty. Give every segment a unique non-empty `segment_id`, an inclusive `source_pages` object with `start` and `end`, an ordered non-empty list of evidence `markdown_blocks`, and exactly one check for each category:

`text`, `hierarchy`, `reading_order`, `tables`, `formulas`, `footnotes`, `links`, `captions`, `images`.

Each check has exactly `category`, `status`, `evidence`, and `finding_ids`. Use `pass`, `difference`, or `ambiguous`; provide non-empty evidence in all cases. A pass has no finding IDs. Every other check references findings of the matching category and kind.

Order segments by source-page range, Markdown block range, then segment ID. `boundaries` must cover every adjacent pair in that order exactly once across cumulative rounds. Each boundary has exactly `before_segment_id`, `after_segment_id`, `status`, `evidence`, and `finding_ids`, using the same pass/difference/ambiguous rules.

Each finding has exactly:

```json
{
  "finding_id": "finding-0001",
  "kind": "difference",
  "category": "text",
  "source_pages": {"start": 1, "end": 1},
  "markdown_blocks": ["block-id-from-evidence"],
  "summary": "Specific content-semantic mismatch",
  "evidence": ["What the frozen source proves"],
  "action": "correct_markdown",
  "status": "open"
}
```

For ambiguity use `kind: ambiguity`, `action: user_decision_required`, and `status: unresolved`. Bind every finding to at least one submitted check or boundary. Its pages and blocks must fall inside the segment or adjacent pair that cites it.

Use `page_misc` for page numbers, running headers or footers, watermarks, print marks, or similar material. Each item has exactly `misc_id`, `kind`, `treatment`, `source_pages`, `semantic_basis`, and `status`. Use `omitted`, `merged`, `relocated`, or `preserved`, a non-empty semantic basis, and `status: justified`.

Use `absence_basis` only when evidence verifies that one review category is absent over a page range. Each item has exactly `absence_id`, `category`, `source_pages`, `basis`, and `status: verified_absent`.

Choose the top-level status consistently:

- `local_complete`: complete page, block, and boundary coverage; no findings; structural validation passes.
- `correction_required`: complete coverage; at least one finding; every finding is a difference.
- `review_ambiguity`: complete coverage; at least one finding; every finding is an ambiguity.
- `review_incomplete`: at least one real coverage gap; no findings. Continue later rather than treating sampled coverage as complete.

One record cannot mix difference and ambiguity findings. Never omit one class, relabel evidence, or guess merely to satisfy the schema.

## Ambiguity Decisions

In confirm mode, resolve `action_required: resolve_review_ambiguity` with a strict object containing one decision for every unresolved finding:

```json
{
  "schema_version": 1,
  "decisions": [
    {
      "finding_id": "finding-0001",
      "resolution": "keep_current",
      "selected_content": null,
      "basis": ["The user's explicit decision"]
    }
  ]
}
```

Use `keep_current` with `selected_content: null`, or `correct_markdown` with a non-empty exact `selected_content`. Supply a non-empty user basis for every item. Submit every finding exactly once. Do not make this decision for the user.

All `keep_current` decisions produce `local_complete`. Any `correct_markdown` decision converts the selected ambiguities into open difference findings and returns `record_correction`. Auto mode stops at `awaiting_user / review_ambiguity`; an explicit mode override to confirm is required before the workflow issues a decision action.

## Correction Record

Submit a strict object with `schema_version: 1` and a non-empty `corrections` list. Correct every open difference exactly once. A Markdown correction item has exactly:

```json
{
  "correction_id": "correction-item-0001",
  "finding_id": "finding-0001",
  "category": "text",
  "source_pages": {"start": 1, "end": 1},
  "markdown_blocks": ["block-id-from-review"],
  "review_segment_ids": ["segment-0001"],
  "affected_boundaries": [
    {"before_segment_id": "segment-0001", "after_segment_id": "segment-0002"}
  ],
  "anchor": {
    "start_byte": 0,
    "end_byte": 4,
    "expected_text": "teh ",
    "expected_sha256": "sha256:<hash-of-exact-anchor-bytes>"
  },
  "replacement": "the ",
  "basis": ["Source page 1 clearly shows the corrected text"],
  "representation": "markdown",
  "fallback": null
}
```

Copy `category`, `source_pages`, and `markdown_blocks` exactly from the finding. `review_segment_ids` is the complete set of segments whose checks or cited boundary contain the finding. `affected_boundaries` is the complete set of recorded adjacent boundaries touching any affected segment. Use exact UTF-8 byte offsets into the reviewed target; `expected_text` and its SHA-256 must match those bytes and remain within the declared blocks. Anchors must not overlap.

For an ambiguity converted to a difference, use the workflow-recorded `selected_content` exactly as the replacement. For every correction, record a non-empty source-evidence basis. Do not submit style edits, summaries, translations, formatting preferences, or unverified completion.

## Fidelity Fallback

Use representations in this order.

For `safe_html`, keep the common correction fields, use an HTML `replacement`, and record:

```json
{
  "representation": "safe_html",
  "fallback": {
    "markdown": {"status": "insufficient", "reasons": ["Specific limitation"]},
    "html": {"status": "sufficient", "reasons": ["Why safe HTML preserves it"]}
  }
}
```

The complete corrected document must pass the finite safe-HTML and URL profiles. Never use scripts, styles, event handlers, iframe/object/embed, dangerous schemes, or editor-private syntax.

For `lossless_crop`, set `replacement` to null, add `crop`, and record why both text representations fail:

```json
{
  "representation": "lossless_crop",
  "replacement": null,
  "fallback": {
    "markdown": {"status": "insufficient", "reasons": ["Specific limitation"]},
    "html": {"status": "insufficient", "reasons": ["Specific limitation"]},
    "visual_object": {"kind": "diagram", "reasons": ["Spatial meaning is essential"]}
  },
  "crop": {
    "page_number": 1,
    "coordinate_space": "page-png-pixels-v1",
    "bbox": {"x0": 10, "y0": 20, "x1": 300, "y1": 220},
    "whole_page_visual_object": false,
    "alt_text": "Concise description of the preserved visual object"
  }
}
```

Use integer coordinates inside the bound page PNG. Do not use an editable-body-text visual kind. A crop covering at least 95 percent of the page requires `whole_page_visual_object: true` and `visual_object.kind: whole_page`; do not make either claim for a smaller crop. The workflow reads and verifies the frozen page image, performs the crop, writes a lossless PNG under `04-review/assets/`, and records its source page, region, dimensions, hash, and size. Never provide or fabricate output bytes, paths, or hashes.

The correction operation preserves the raw Markdown and extraction tree, writes a separate corrected Markdown and diff, rebases existing local file references to the same bundle files, and rejects missing, escaping, linked, special, or drifting resources.

## Follow-Up Review And Final Pointer

A committed correction returns `conversion_state: review_pending`, `action_required: record_review`, a new generation, and fresh evidence bound to the corrected target. Fresh mode resets required page and Markdown-block coverage; do not reuse prior pass conclusions as the new round. Inspect the corrected target, its resources, every affected area, and every required boundary, then submit another full review record.

There is no separate finalize command. A successful `local_complete` review or an all-keep ambiguity decision atomically writes `final_markdown`. Accept only the pointer returned by `inspect` or the record command. It identifies the raw conversion or corrected Markdown and binds its path, SHA-256, size, review round and evidence hashes, GFM dialect, and semantic hash.
